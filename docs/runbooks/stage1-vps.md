# Runbook Этапа 1: профиль `balbes` на VPS одной командой

## Цель

Runbook описывает развёртывание профиля dsh `balbes` на VPS с Ubuntu одной
командой: установка окружения (Node, pnpm, git) и глобального dsh,
синхронизация профиля из репозитория, приём ключа DeepSeek и ручная
smoke-проверка.

Профиль `balbes` собирается из бандлов `@deepseek-ai/dsh-base` и
`@deepseek-ai/dsh-headless`; веб-интерфейс (`dsh-web-app`) в него **не входит**.
Headless — одноразовый инструмент для smoke-задачи, а не серверный демон,
поэтому установка ничего не слушает и свободный порт не нужен.

Критерий готовности этапа: по этому runbook'у профиль разворачивается на VPS и
smoke-проверка проходит (исполняется на реальном сервере в конце этапа).
Источник профиля и скриптов — репозиторий
https://github.com/mdikarev/dsh-balbes-server, ветка `main`.

## Требования

- Ubuntu (установщик использует `apt`; целевая — свежая Ubuntu LTS).
- Пользователь с правами `sudo` — для установки системного Node и глобального dsh.
- `curl` — для скачивания установщика (если нет: `sudo apt-get install -y curl`).
- Доступ в интернет: `raw.githubusercontent.com`, npm registry и API DeepSeek.
- Свободный порт **не нужен**: профиль не поднимает ни headless-часть как
  сервис, ни веб-морду.

## Установка одной командой

Установка выполняется скриптом `scripts/install.sh` из репозитория
(создаётся в рамках Этапа 1; этот runbook фиксирует контракт команды):

```bash
curl -fsSL https://raw.githubusercontent.com/mdikarev/dsh-balbes-server/main/scripts/install.sh | bash
```

В ходе выполнения скрипт интерактивно запросит DeepSeek API key. Запрос читается
напрямую с терминала (`/dev/tty`), поэтому он работает даже при запуске через
конвейер `curl ... | bash` (stdin скрипта в этом случае — конвейер, а не
терминал). Пустой ввод пропускает установку ключа.

Чтобы не вводить ключ вручную, экспортируйте переменную окружения заранее (без
`export` её увидит только curl, а не bash, исполняющий скрипт):

```bash
export DEEPSEEK_API_KEY=sk-ваш-ключ
curl -fsSL https://raw.githubusercontent.com/mdikarev/dsh-balbes-server/main/scripts/install.sh | bash
```

Скрипт идемпотентен: повторный запуск безопасен и работает как обновление
(см. раздел «Обновление»).

## Что делает установщик (по шагам)

1. **Окружение.** Если `node --version` ниже 22 — подключает репозиторий
   NodeSource и ставит Node 22 LTS через `apt`; если нет pnpm — ставит его
   глобально через npm; если нет git — ставит `git` через `apt`.
2. **dsh.** Если команда `dsh` отсутствует — ставит глобально:
   `sudo npm i -g @deepseek-ai/dsh`.
3. **Репозиторий.** Клонирует https://github.com/mdikarev/dsh-balbes-server в
   `$HOME/dsh-balbes-server` (или в каталог из `$DSH_BALBES_REPO_DIR`, если он
   задан); если клон уже есть — обновляет его через `git pull --ff-only`.
4. **Профиль.** Синхронизирует `profiles/balbes` из репозитория в
   `$DSH_HOME/profiles/balbes`. Профиль в репо — источник правды, поэтому
   перезапись при синхронизации актуальна.
5. **Ключ.** Если `DEEPSEEK_API_KEY` не задан в окружении — запрашивает ключ
   интерактивно, читая его с терминала (`/dev/tty`), и записывает в
   `$DSH_HOME/.credentials.yaml` (при создании файл получает права `600`).
   Если файл уже существует с другими записями — чужие секции не
   перезаписываются: скрипт предупреждает и показывает формат для ручной
   правки.
6. **Проверка композиции.** Запускает `dsh --profile balbes --dump-config`;
   падение считается ошибкой установки.
7. **Финал.** Печатает команду smoke-проверки (см. следующий раздел).

Переменные окружения, которые учитывает установщик:

- `DEEPSEEK_API_KEY` — ключ DeepSeek (иначе интерактивный ввод);
- `DSH_HOME` — каталог данных dsh (по умолчанию `$HOME/.dsh`);
- `DSH_BALBES_REPO_DIR` — каталог клона репозитория (по умолчанию
  `$HOME/dsh-balbes-server`).

## Smoke-проверка

Установщик **не запускает LLM автоматически** (продуктовое решение): smoke
выполняется вручную одной командой:

```bash
dsh --profile balbes "Напиши 'ok' и больше ничего"
```

Ожидаемый результат: код возврата `0`, в stdout — финальный ответ ассистента
(короткое «ok»). Ошибка авторизации на этом шаге — см. «Ключ не принят» в
разделе устранения неполадок.

## Обновление

Профиль — манифест в репозитории, поэтому обновление сводится к повторной
синхронизации профиля и, при необходимости, обновлению самого dsh.

- **Повторный запуск установщика** — та же команда `curl | bash`: подтянет
  репозиторий (`git pull`), пересинхронизирует `profiles/balbes` и проверит
  композицию. Ключ при запросе можно пропустить (пустой ввод).
- **Вручную** — если не хочется запускать установщик целиком:

```bash
git -C "$HOME/dsh-balbes-server" pull --ff-only
cp -R "$HOME/dsh-balbes-server/profiles/balbes" "${DSH_HOME:-$HOME/.dsh}/profiles/balbes"
```

Новая версия самого dsh ставится глобально:

```bash
sudo npm i -g @deepseek-ai/dsh
```

## Устранение неполадок

### Нет Node 22 и выше

Установщик ставит Node 22 LTS сам, но если этот шаг не сработал — установите
вручную через NodeSource:

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
node --version   # должно показать v22.x
```

### Битые registry-версии: почему нельзя `pnpm add` базовые бандлы

npm registry публикует устаревшие сломанные версии пакетов
`@deepseek-ai/dsh-*` (например, `dsh-headless@0.0.1-rc.1` зависит от
несуществующего пакета). Поэтому базовые бандлы (`@deepseek-ai/dsh-base`,
`@deepseek-ai/dsh-headless`) **нельзя** добавлять в `dependencies` профиля и
ставить через pnpm.

Профиль в репозитории — только манифест (`package.json` с `dsh.profile.bundles`
и `cordis.patch.yml`), без `node_modules`. Бандлы резолвятся из зеркала
установленного dsh: `$DSH_HOME/profiles/node_modules` — симлинки на каталог
установки dsh. Если `dsh --profile balbes --dump-config` падает с ошибкой
«бандл не найден» — переустановите dsh (`sudo npm i -g @deepseek-ai/dsh`) и
повторите синхронизацию профиля; `pnpm add` проблему не решит.

### Ключ не принят (ошибка авторизации при smoke)

Проверьте, что ключ записан в `$DSH_HOME/.credentials.yaml` и файл доступен
только владельцу:

```bash
ls -l "${DSH_HOME:-$HOME/.dsh}/.credentials.yaml"   # ожидается -rw-------
chmod 600 "${DSH_HOME:-$HOME/.dsh}/.credentials.yaml"
```

Ключ хранится в секции `refs` под именем `DEEPSEEK_API_KEY`. При создании файла
установщик пишет его целиком (поля `version`, `refs`, `records`); если файл уже
существовал с другими записями — установщик его не перезаписывает, и ключ нужно
добавить вручную в секцию `refs`:

```bash
version: 1
refs:
  DEEPSEEK_API_KEY: sk-ваш-ключ
```

Другие секции файла при ручной правке не трогайте. Изменения подхватываются при
следующем запуске dsh; права на файл должны остаться `600`.

### Профиль не найден

`dsh --profile balbes ...` сообщает, что профиль не найден, — проверьте, что
профиль синхронизирован в каталог данных:

```bash
ls -la "${DSH_HOME:-$HOME/.dsh}/profiles"          # в списке — каталог balbes
ls "${DSH_HOME:-$HOME/.dsh}/profiles/balbes/package.json"
```

По умолчанию `$DSH_HOME` — это `~/.dsh`; если задавался другой `DSH_HOME`,
профиль ищется там. Каталога нет — пересинхронизируйте профиль из репозитория
(см. «Обновление») или запустите установщик заново.

## Где лежат данные

Все данные dsh находятся в каталоге `$DSH_HOME` (по умолчанию `~/.dsh`):

- `profiles/` — установленные профили: `profiles/balbes` (синхронизируется из
  репозитория) и `profiles/node_modules` (симлинки-зеркало на установку dsh);
- `.credentials.yaml` — ключи API (права `600`);
- сессии и настройки (settings) dsh.

Профиль воспроизводим из репозитория, а ключи, сессии и настройки в репозиторий
не коммитятся и больше нигде не хранятся: удаление `$DSH_HOME` теряет их
безвозвратно (ключ затем вводится заново, профиль — пересинхронизируется).
