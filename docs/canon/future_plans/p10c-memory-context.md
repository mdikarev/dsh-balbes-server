# Доставка памяти в контекст

- Status: draft
- Depends: p10a
- Focus: ядро памяти, карта, инструменты `recall` и `remember`

## Intent

Хранилище (p10a) бесполезно, пока знание не попадает в задачу. Этот слой
описывает, как память подмешивается в контекст агента: небольшое ядро всегда,
компактная карта памяти, и полные записи по требованию. Сегодня секция
промпта не видит текущее сообщение (`AssembleContext` содержит только `scope`
и `signal`), но наш dispatch (`runner.ts` для `/api/prompt` и `agentTask.ts`
для Telegram) держит промпт до старта агента — это и есть шов для пуш-доставки.
Слой не меняет агентский цикл dsh и работает через штатные швы.

## In scope

- Ядро памяти: пиннутый слой записей, инжектируемый через
  `ctx.systemPrompt.section(...)` с жёстким бюджетом (аналог того, как дом
  отдаёт `agent/self.md`).
- Карта памяти: компактный список заголовков/тегов доступных записей, чтобы
  модель знала, что память есть и про что она.
- Инструменты модели: `recall` (поиск/чтение записей) и явный `remember`
  (запись по инициативе модели), зарегистрированные через
  `ctx.tools.register(defineTool(...))`.
- Режим доставки: pull (модель тянет), push top-K на старте задачи или гибрид;
  выбор фиксируется дизайном.
- Отбор: фильтр по scope (глобальный дом + текущий проект) и бюджет контекста;
  провенанс записи виден в подмешанном тексте.
- Совместимость: память не становится вторым источником истины о состоянии
  задачи; сессионная память движка не затрагивается.

## Out of scope

- Автоматическое извлечение знания из задач и компактизация — p10d.
- Семантический/векторный retrieval и внешние embedding-сервисы — отдельный
  горизонт; сначала полнотекстовый/структурный отбор.
- Управление содержимым памяти из админки — p10b.
- Память диалога внутри сессии — её держит движок dsh.
- Изменение или обход агентского цикла dsh, правка установленных
  `@deepseek-ai/*`.

## Absorbs into

- ARCHITECTURE.md — доставка памяти: ядро, карта, инструменты, режим и бюджет.
- GLOSSARY.md — термины «ядро памяти», «карта памяти».
- ADMIN_UI.md — состояния, если доставка проявляется в интерфейсе.
- API_CONTRACTS.md — если у памяти появляется серверная поверхность чтения.
- OVERVIEW.md — место доставки памяти в сигналах успеха.
