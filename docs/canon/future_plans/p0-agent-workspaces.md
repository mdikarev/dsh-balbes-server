# Воркспейсы на сервере: дом агента и проекты

- Status: absorbed

## Intent

Направление реализовано (первый шаг — сами воркспейсы на сервере) и его исходы
абсорбированы в живые секции canon (ARCHITECTURE.md, OVERVIEW.md, GLOSSARY.md,
ADMIN_UI.md, API_CONTRACTS.md). Ниже — исходная формулировка направления для
истории и будущих шагов (git/ключи, сессии/чат, наполнение дома — отдельные
последующие инициативы).

## In scope

- Понятие «воркспейс» как серверная сущность; типы: домашний агентский и
  проекты.
- Домашний воркспейс: зарезервированный, создаётся автоматически при
  установке/первом старте сервера, существует всегда; пользователем не
  создаётся и не удаляется.
- Расположение: дом — `$DSH_HOME/agent/`; проекты — `$DSH_HOME/projects/<имя>/`.
  Пространства имён раздельные, коллизий имён нет (дом — не проект).
- Реестр воркспейсов ведётся сервером (`projects.json` в доме); сервер умеет
  отдавать список воркспейсов (API), админка — показывать его.
- Создание воркспейса через админку: новый проект (пустой каталог + имя).
- Удаление воркспейса через админку: удаляется проект (каталог и запись
  реестра), с подтверждением; домашний воркспейс не удаляется — он
  зарезервирован.
- Проект — обычный каталог-воркспейс; правила проекта (`AGENTS.md` и т.п.) —
  файлы внутри, ими владелец управляет напрямую.
- Владелец всегда главнее: файлы воркспейсов — обычные файлы, доступны для
  ручного редактирования в любой момент.

## Out of scope

- Git: импорт/клонирование из GitHub/GitLab, ключи и токены для git — отдельная
  будущая настройка (своя инициатива).
- Сессии и чат, привязка сессий к воркспейсу, исполнение задач агентом внутри
  воркспейса — последующая инициатива.
- Наполнение дома: состав файлов (`self.md`, `skills/`, `notes/`), глобальные
  правила и скиллы агента — последующие шаги.
- Чат-команды, синтаксис команд, детали интерфейса (имена разделов, внешний
  вид) — проектируются вместе с админкой/чатом.
- Автономное изменение агентом своих правил, долговременная память,
  самообучение, каналы.

## Absorbs into

- ARCHITECTURE.md — сущность воркспейс, пути `$DSH_HOME/agent|projects`, реестр,
  API и раздел админки.
- GLOSSARY.md — термины: воркспейс, дом агента, проект.
- OVERVIEW.md — scope и этапы.
- ADMIN_UI.md — страница воркспейсов (внешний вид — по мере реализации UI).

## Open questions

- Переименование воркспейсов — не входит в первый шаг; когда и как появится.
- Представление «дома» в реестре и UI: отдельная секция, а не имя проекта.
- Что именно появляется в новом проекте «с нуля»: пустой каталог или стартовый
  набор файлов.
- Удаление: насколько глубокое (весь каталог), подтверждение в UI — детали
  реализации.
- Границы первого шага по API/админке: только «список + создать + удалить» или
  сразу базовые операции над воркспейсом.
