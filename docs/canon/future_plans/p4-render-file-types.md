# Рендер файлов по типу: Markdown и подсветка кода

- Status: absorbed
- Design: `docs/superpowers/specs/2026-09-20-render-file-types-design.md`

## Intent

Владелец читает файл воркспейса в админке так, как он задуман: markdown — как
отрендеренный документ, код — с подсветкой синтаксиса. Инициатива p3-file-view
даёт read-only чтение файла как моноширинного текста; эта инициатива описывает
следующий шаг — отображение по типу содержимого, не покидая файловый таб.

## In scope

- Определение типа отображения поверх уже прочитанного `WorkspaceFileResult`
  (форма `text`), без изменения серверного контракта чтения.
- Markdown: рендер в форматированный документ (заголовки, списки, таблицы,
  ссылки, блоки кода) с переключением «просмотр / исходник».
- Подсветка синтаксиса для языков кода с определением языка по расширению пути
  (для файлов без расширения — по shebang); безопасный фолбэк на текущий
  моноширинный текст для неизвестных языков.
- Сохранение уже принятых свойств p3: read-only, контеймент воркспейса, лимит
  `DEFAULT_MAX_FILE_BYTES` = 256 КиБ с флагом `truncated`, симлинки не
  разыменовываются, три формы ответа.
- Безопасность клиентского рендера: markdown санитизируется, встроенный
  HTML/скрипты не исполняются, ссылки не ломают контеймент воркспейса.
- Расширение целиком на стороне SPA поверх существующей ручки
  `workspaces.file`; серверный контракт по возможности не меняется.

## Out of scope

- Редактирование, сохранение, создание, загрузка и скачивание файлов.
- Рендер бинарных форматов (изображения, PDF, офисные документы) — отдельная
  возможность.
- Пагинация и живое обновление открытого файла.
- Права и роли: сервер single-user, доступ владельца не разграничивается.
- Настройки темы подсветки, экспорт и печать документа, оглавление документа.

## Absorbs into

- ADMIN_UI.md — режимы отображения файлового таба, переключатель
  «просмотр / исходник», подключение markdown-рендера и подсветки.
- ARCHITECTURE.md — клиентский слой рендера файлов и его место относительно
  ручки `workspaces.file`.
- GLOSSARY.md — термины «рендер файла по типу», «подсветка синтаксиса», «режим
  просмотра markdown».
- API_CONTRACTS.md — только если форму `WorkspaceFileResult` потребуется
  уточнить (ожидаемо без изменений).
- OVERVIEW.md — при появлении пользовательски заметного поведения.

## Open questions

Пусто: вопросы закрыты утверждённым дизайном — язык подсветки определяется по
расширению пути (для файлов без расширения — по shebang), markdown рендерится
клиентски через `react-markdown` + `remark-gfm` с санитизацией (сырой HTML не
исполняется), fenced code и standalone-код используют общий движок
`rehype-highlight`/`highlight.js`, переключатель «просмотр/исходник» для `.md`
по умолчанию «просмотр» и не персистится, большие markdown в пределах лимита
256 КиБ рендерятся как есть.
