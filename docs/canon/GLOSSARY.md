# Glossary

## How to use

Термины canon используются единообразно во всех секциях canon, в спеке, планах,
runbook и коде. Если термин из этого списка встречается в проекте — он означает
именно то, что зафиксировано здесь.

## Terms

### dsh
DeepSeek Harness — лоадер профилей и платформа расширений. Профиль =
`dsh.profile.bundles` + свой слой патчей; функции dsh — Cordis-компоненты
(бандлы/плагины). В этом проекте dsh — зависимость, не форк.

### Профиль (profile)
Каталог `$DSH_HOME/profiles/<name>` (в репозитории — `profiles/<name>/`) с
манифестом `package.json` (`dsh.profile.bundles` — список бандлов,
`patchReload: startup | live`), слоем патчей `cordis.patch.yml` и
`pnpm-workspace.yaml`. Один профиль = одна поверхность dsh.

### Бандл (bundle)
npm-пакет с декларацией `dsh.bundle.patch` (указывает на свой
`cordis.patch.yml`); поставляет патч-слой композиции. Бандл из списка `bundles`
обязан иметь такую декларацию, иначе старт падает громко. Примеры:
`@deepseek-ai/dsh-base`, `dsh-balbes-host`.

### Плагин (plugin)
Обычный Cordis-плагин без `dsh.bundle.patch`: сервис, api-роут, тул, ui-плагин.
Подключается записями `insert: {id, name}` в патч профиля.

### Патч (patch) / `cordis.patch.yml`
Слой композиции: YAML-массив записей — переопределение конфига по `id`
(заменяет конфиг целиком, deep-merge нет), отключение (`disabled: true`) и
`insert` новых записей под уникальными `id`. Пустой или только-комментарный
файл роняет старт — отключение слоя пишется как `[]`.

### Host
Транспортный слой внутри процесса dsh (HTTP-роуты, раздача статики), а не
«сервер на каждую интеграцию». Штатная морда dsh (`dsh-web-app`) не
используется; наш host — собственный бандл `dsh-balbes-host` (плагины
`startup`/`server`/`auth`/`static`/`api`) в том же процессе dsh. Host раздаёт
API (только POST, R-API-1) и SPA-админку; будущие каналы — другие плагины
того же процесса, клиенты того же API.

### `dsh-balbes-host`
Собственный Cordis-бандл над `dsh-base`: `cordis.patch.yml` (persona, PTC-
режим, `code-runtime`, вставки плагинов) + плагины по экспортным подпутям.
Приложение профиля: `dsh --profile balbes` поднимает сервер и держит процесс
(в отличие от one-shot headless); процесс живёт, пока слушает HTTP-сервер,
и аккуратно закрывается по SIGTERM (dispose плагинов).

### `dsh-balbes-admin`
Админка — React SPA (Vite), НЕ плагин dsh: статика, которую host раздаёт
браузеру; общается с сервером только по HTTP API (JWT в localStorage,
`Authorization: Bearer`). Связь «агентский сервис ↔ клиенты»: будущие каналы —
клиенты того же API.

### `dsh-balbes-contracts`
Пакет чистых TS-типов API-контрактов (запросы/ответы/`ApiErrorBody`).
Импортируется SPA-клиентом; host держит структурные формы — соответствие
проверяется REAL-тестами и typecheck. Человекочитаемый реестр —
секция API_CONTRACTS.md.

### `admin-auth.json`
Учётные данные админки в `$DSH_HOME` (600): `{login, passwordHash, jwtSecret,
createdAt}`. Пароль — только scrypt-хэш, открытый текст не хранится (печать
один раз при генерации). Сброс пароля ротирует `jwtSecret`: выданные JWT
становятся недействительными.

### Воркспейс (workspace)
Серверная сущность «рабочее место агента» — каталог в `$DSH_HOME`. Два типа:
дом агента и проект. Источник правды о составе — каталоги на диске (реестр —
индекс); файлы внутри воркспейса — обычные файлы, владелец правит их напрямую.
Правила проекта (`AGENTS.md` и т.п.) — файлы внутри, ими владелец управляет
сам.

### Дом агента (agent home)
Зарезервированный воркспейс агента `$DSH_HOME/agent/`: создаётся
автоматически при первом старте сервера, существует всегда; пользователем не
создаётся и не удаляется (вне корня проектов, операциям проектов недостижим).
Стартовый набор дома (`AGENTS.md`, `self.md`, `skills/`) создаётся сервером
при первом старте — только отсутствующие файлы, без перезаписи правок
владельца. Дом — глобальный слой контекста процесса: его правила,
самоописание и скиллы действуют во всех воркспейсах (см. «Глобальный контекст
дома»). Наполнение вне глобального контекста (`notes/`, долговременная
память) — последующие шаги.

### Глобальный контекст дома (agent home global context)
Правила, самоописание и скиллы, которые дом `$DSH_HOME/agent/` даёт всем
агентам процесса — Telegram-задачам и админскому тестовому промпту. Порядок
слоёв — global → project: правила `agent/AGENTS.md` (user-global) рендерятся
первыми, затем проектная цепочка `<project>/AGENTS.md` от корня проекта к
`cwd` (более конкретный файл главнее); `agent/self.md` подключается секцией
`balbes:self` системного промпта; скиллы `agent/skills/` глобальны,
`<project>/.dsh/skills/` — локальны для проекта. Файлы дома владелец правит
напрямую, изменения подхватываются без переустановки. Проектные правила
(`<project>/AGENTS.md`) работают штатной цепочкой инструкций dsh.

### `self.md`
Файл самоописания дома `$DSH_HOME/agent/self.md`: плагин `dsh-balbes-home`
включает его содержимое в системный промпт синхронной секцией `balbes:self`
(order 100). Отсутствие или нечитаемость файла → пустая секция (без падений),
символы `{{` экранируются. Владелец пишет файл свободно и правит напрямую.

### Глобальные и проектные скиллы
Скиллы дома `$DSH_HOME/agent/skills/` действуют во всех воркспейсах
(глобальный слой); скиллы проекта `<project>/.dsh/skills/` — только в своём
проекте (нативный project-корень). При совпадении имени проектный скилл
затеняет домашний. Формат — каталог `<name>/SKILL.md` или плоский
`<name>.md` с frontmatter `name`/`description`; стартовый `README` дома —
инструкция по формату, а не скилл.

### Проект (project)
Воркспейс-каталог `$DSH_HOME/projects/<имя>/`. Имя — строгий slug
(`[A-Za-z0-9._-]`, ≤ 64, без `/`, `..`, пробелов и ведущих/хвостовых точек),
равно имени каталога. Создаётся/удаляется через админку/API: при создании
идемпотентно создаётся `<project>/.dsh/skills/README` (проектные скиллы), а
удаление — рекурсивное, с подтверждением в UI. Любой каталог под корнем
проектов — проект, создан он через API или руками.

### `dsh-balbes-workspaces`
Пакет-плагин воркспейсов (`packages/plugins/dsh-balbes-workspaces`): сервис
`balbesWorkspaces` + доменные функции (валидация имени, обеспечение дома,
list/create/delete проектов, чтение/запись/согласование реестра). Не бандл
(без `dsh.bundle.patch`): подключается insert-записью в патч профиля и
копируется в `node_modules` профиля установщиком и CI.

### `dsh-balbes-home`
Функциональный плагин глобального контекста дома
(`packages/plugins/dsh-balbes-home`): инжектит `systemPrompt` и регистрирует
секцию `balbes:self` с содержимым `agent/self.md`. Правилами и скиллами не
управляет — за них отвечают нативные швы `agent-instructions` и
`skill-filesystem`. Не бандл (без `dsh.bundle.patch`): подключается
insert-записью в патч профиля и копируется в `node_modules` профиля
установщиком.

### Telegram-канал

Плагин `dsh-balbes-telegram` внутри единственного dsh-процесса: long polling
Telegram Bot API для одного разрешённого владельца, только private chat.
Token хранится через `ctx.credentials`, user ID и enabled — в settings-namespace
`balbes-telegram`; настройка выполняется из админки. Канал не является отдельным процессом и не
соединяется с телефоном напрямую. Задачи канала выполняются с полной поверхностью
инструментов процесса — той же, что у Web-агента (отдельного per-agent
allow-фильтра и read-guard нет), а границы — sandbox-политика процесса и
approval; состояние polling и session mapping переживают рестарт через
`$DSH_HOME/telegram-state.json`.

Командная поверхность канала: `/menu` (`/start`), `/status`, `/ws`, `/model`,
`/reset`, `/stop`, `/help`. Команды регистрируются нативными ручками Bot API
(`setMyCommands`, `setChatMenuButton`), поэтому владелец вызывает меню из
любой точки диалога; список команд и роутинг текста берутся из одного
источника, а текст, начинающийся со «/», никогда не уходит агенту как задача.

Карточка прогресса — одно редактируемое сообщение о ходе задачи (шаги
инструментов из белого списка полей, todo-список агента, время, финальная
квитанция «готово/остановлено/ошибка»). Это НЕ streaming ответа модели:
результаты инструментов и текст ответа в карточку не попадают, а потоковая
доставка ответа остаётся отдельным этапом.

Остановка задачи двух видов: сброс контекста (`/reset`, с подтверждением)
уничтожает сессию, а `/stop` отменяет активную задачу и очищает очередь,
сохраняя сессию и контекст.

### AgentTaskService

Внутренний сервис workspace-aware задач. Использует штатный dsh agent loop,
создаёт/возобновляет session, задаёт `meta.cwd` после containment-проверки,
сериализует задачи одного воркспейса и возвращает финальный ответ каналу.
Сессия закрепляется за воркспейсом (persistent, возобновляется после рестарта),
очередь — до 3 ожидающих задач, сброс контекста завершает сессию, а остановка
(`cancel`) отменяет активный turn и ожидающие задачи, не завершая сессию.
Выбор модели сервис читает на каждый запрос (живой selection над глобальным
дефолтом `agentDefaultModel`), поэтому смена дефолта применяется к живой сессии
со следующего шага без потери контекста.
Telegram — первый потребитель; сервис не заменяет агентский цикл dsh.

### `projects.json`
Реестр-индекс воркспейсов в `$DSH_HOME` (600): `{version, projects:
{<имя>: {createdAt}}}`. Хранит только метаданные, которых нет у каталога
(сейчас — `createdAt`); запись атомарная (tmp+rename). Строки без каталога
вычищаются при list/записи; ручные каталоги видны без строки (createdAt —
прочерк). Дом в реестре не хранится.

### Реестр сессий воркспейса
Файл `$DSH_HOME/workspace-sessions.json` (600): принадлежность сессий
воркспейсам — `{version, workspaces: {<ключ воркспейса>: [{sessionId,
channel}]}}`. Append-only: записи добавляются upsert'ом по `sessionId` и
чтением не переписываются. Хранит только принадлежность: заголовок и время
сессии берутся из движка.

### Ключ воркспейса
Идентификатор воркспейса в реестрах: `home` — дом агента,
`project:<имя>` — проект. Тот же формат использует session mapping
Telegram-канала.

### Канал сессии
То, что создало сессию воркспейса: `telegram` — задачи из Telegram-канала.
Хранится в реестре сессий воркспейса рядом с `sessionId`.

### Подключение (модель/провайдер)
Строка в разделе «Модели» админки: подключение провайдера моделей, на
котором работает сервер. Состоит из вида `deepseek` (официальный DeepSeek:
закреплён, URL фиксирован, только ключ), `preset` (каталоговый провайдер
движка dsh: официальный URL/протокол берутся из каталога движка, задаются
ключ и модели; опциональный `baseURL` — override «свой URL») или `custom`
(OpenAI-совместимый, «Свой URL»), имени, опционального `baseURL` и одного
API-ключ-реф в `$DSH_HOME/.credentials.yaml`. Значение ключа API не
возвращает — только признак `hasKey`; запись/сброс ключа идут через сервис
`ctx.credentials`.

### Дефолтная модель
Глобальный выбор модели сервера: `{provider, model}` (`provider` = routeId
подключения) в settings-секции `agent-default-model`; устанавливается
в разделе «Модели». Применяется к следующим запросам `/api/prompt` —
без рестарта сервера.

### R-API-1
Правило API: все запросы к `/api/*` — только POST (исключение — статика SPA,
это не API). Ошибки — тело `{error:{code,message}}`.

### Headless
`@deepseek-ai/dsh-headless` — one-shot драйвер: одна задача из CLI → финальный
ответ в stdout → exit. Исторический smoke-инструмент этапа 1; начиная с этапа 2
в профиль `balbes` не входит (заменён host-бандлом).

### `$DSH_HOME`
Каталог данных dsh (по умолчанию `~/.dsh`): `profiles/`, `.credentials.yaml`,
сессии, настройки. Уважается установщиком и runbook'ом.

### Mirror установки (`$DSH_HOME/profiles/node_modules`)
Симлинки-зеркало на каталог установки dsh, через которое резолвятся базовые
бандлы профиля. Поэтому базовые бандлы не кладутся в `dependencies` профиля и
не ставятся через pnpm (registry содержит сломанные устаревшие версии).

### Smoke
Ручная проверка работоспособности сервера: вход в админку / `curl` с JWT —
`POST /api/auth/login` → `POST /api/prompt` с реальным ответом модели
(этап 1: headless-CLI `dsh --profile balbes "<задача>"`). Установщик LLM
автоматически не запускает; автотесты в модель не ходят (R-TEST-1).

## Naming conventions

- Пакеты надстройки: `dsh-balbes-<роль>` (kebab-case); неймспейс
  `@deepseek-ai` не занимается.
- Файлы: kebab-case; функции/переменные camelCase; классы/типы PascalCase;
  константы UPPER_SNAKE; булевы — `is*/has*/should*`. Код и комментарии — на
  английском.
- Один профиль на поверхность; имя профиля — `<name>` в
  `$DSH_HOME/profiles/<name>` и в `profiles/<name>/` репозитория.
