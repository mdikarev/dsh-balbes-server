# Admin UI

## Purpose

Зафиксировать визуальную систему админки `dsh-balbes-admin` — характер
интерфейса, палитру и семантические токены, типографику, геометрию, компоновку,
компоненты и состояния — как единый источник решений для всех экранов.

`Target design v1` — утверждённый целевой визуальный контракт. Значения в нём
проектные, а не измерения текущей реализации: наличие значения здесь не означает,
что оно уже реализовано или проверено в браузере. `Current state` описывает
реализованное поведение, которое визуальный редизайн не меняет.

Основание — исходное направление и два скриншота текущего интерфейса. Числа в
`Target design v1` получены проектированием, а не снятием стилей из кода; при
утверждении репозиторий, `styles.css` и работающая админка не сверялись с ними
значение за значением.

## Scope

- Покрывает: общий стиль, палитру и семантические токены, типографику, размеры,
  отступы, навигационный каркас, типы компоновки, компоненты, состояния,
  адаптивность, UI-копию и критерии визуальной приёмки.
- Применяется ко всем существующим и будущим страницам, вкладкам, диалогам,
  меню, состояниям загрузки и ошибок. Перечисленные в `Current state` экраны —
  примеры применения, а не закрытый перечень экранов репозитория.
- Вне scope: изменение API, авторизации, бизнес-операций, набора провайдеров,
  правил хранения, прав доступа, безопасности и семантики пользовательских
  действий. Функциональные контракты админки, включая Login/Main, JWT в
  localStorage и 401 → logout, остаются в `ARCHITECTURE.md` / `OVERVIEW.md`;
  термины — в `GLOSSARY.md`.
- `Current state` — реализованный снимок; `Target design v1` — целевой контракт.
  При расхождении новым визуальным значением считается `Target design v1`, а
  поведение и данные берутся из `Current state` и функционального канона.

## Current state

Общее направление задаёт текущая реализация (`dsh-balbes-admin`):

- Тёмная dev-tool тема: тёмный фон, поверхности-карточки, светлый текст —
  «рабочий инструмент разработчика», без декоративности.
- Акцентный синий для действий и состояний; сдержанная служебная палитра
  (успех/ошибка); скругления умеренные.
- Моноширинный шрифт для «технического»: имя/бренд, код, диалог сессии.
- Компактная функциональная компоновка: сайдбар + топбар + рабочая область;
  два состояния — экран входа (Login) и основная страница (Main).
- UI-копия на русском, короткая и точная.
- Реализация-референс: `packages/frontend/dsh-balbes-admin/src/styles.css`
  (токены в `:root`), компоненты `Brand`/`Sidebar`/`Topbar`, страницы
  `Login`/`WorkspacesPage`/`ModelsPage`/`TelegramPage`/`MemoryPage`.
- Страница воркспейсов («Проекты» в сайдбаре) — рабочая зона в три колонки под
  топбаром (h1 и пояснение страницы не выводятся; заголовок — в топбаре):
  панель списка воркспейсов (фикс. узкая), содержимое выбранного воркспейса —
  дерево каталогов/файлов (~1/3 остатка), правая зона — контейнер табов
  (плашка сверху, табы описаны данными: первый незакрываемый — «Сессии»,
  поверх него динамические табы открытых сессий и файлов с «×»; кнопка «Обновить»
  справа в плашке; без выбранного воркспейса — заглушка «Выберите
  воркспейс»). Разделитель дерево/правая зона перетаскиваемый.
- Страница целиком не прокручивается: рабочая зона занимает высоту вьюпорта под
  топбаром, и каждая колонка прокручивается независимо — сайдбар, панель списка
  воркспейсов, дерево и правая зона. Скроллер правой зоны — содержимое активного
  таба: список сессий, диалог или файл. Длинное содержимое правой зоны не растягивает
  страницу и не уводит остальные колонки; топбар и плашка табов остаются на месте.
- Таб «Сессии» правой зоны: строки «заголовок · канал · время» (заголовок
  сессии, канал и локальное время создания; новейшие сверху). Строки
  кликабельны (строка — кнопка, работает клавиатура) и открывают диалог
  сессии; открытая строка подсвечена. Состояния — «Загрузка…», «Сессий пока
  нет», ошибка с кнопкой «Повторить».
- Динамические табы сессий: поверх незакрываемого таба «Сессии» открывается
  таб с названием сессии (fallback «Без заголовка») и отдельной кнопкой «×»
  (не вложена в кнопку). Подписи обрезаются с ellipsis, лента табов
  прокручивается горизонтально, `title`-атрибут показывает канал и время для
  различения одноимённых. Повторный клик активирует уже открытый таб; закрытие
  активирует соседний слева таб, иначе «Сессии». Табы и активный таб
  сбрасываются на «Сессии» при смене воркспейса, перезагрузке и уходе со
  страницы — состояние UI-локальное.
- Динамические файловые табы: листья дерева кликабельны (кнопка, работает
  клавиатура и фокус) и открывают файл в таком же динамическом табе правой
  зоны поверх «Сессии»; папки по-прежнему раскрываются, а клик по симлинку
  приводит к сообщению «не открывается». Файловых табов может быть сколько
  угодно; повторный клик фокусирует уже открытый таб; «×» закрывает, активируя
  соседа слева, иначе «Сессии». Подпись таба — имя файла (basename), `title` —
  полный относительный путь для различения одноимённых. Файловые табы
  сбрасываются при смене воркспейса, перезагрузке и уходе со страницы.
- Содержимое файла (`FileView`): отображение по типу содержимого поверх уже
  прочитанного текста. Markdown (`.md`, `.markdown`) — отрендеренный документ
  (заголовки, списки, GFM-таблицы, ссылки, блоки кода) с переключателем
  «Просмотр / Исходник» (по умолчанию «Просмотр»; выбор UI-локальный и не
  персистится). Код известного языка — моноширинный текст с подсветкой
  синтаксиса; неизвестный язык и прочий текст — моноширинный текст без
  подсветки. При обрезании — пометка «Файл показан не полностью (лимит
  256 КиБ)»; пустой файл — «Файл пуст»; бинарный — «Это бинарный файл
  (N байт) — просмотр недоступен»; симлинк — «Символические ссылки не
  открываются». Состояния — «Загрузка…», ошибка с кнопкой «Повторить»; живого
  обновления нет (загрузка при открытии таба и по общей кнопке «Обновить»).
- Диалог сессии (транскрипт): реплики владельца/модели — метка роли и текст
  `pre-wrap`; вызовы инструментов, результаты, системный промпт и служебный
  контекст — свёрнутые `<details>` (разворот по клику), в `<summary>` одна
  строка. Строка вне текущего контекста (`inContext: false`) несёт приглушённую
  пометку «не в контексте». Состояния — «Загрузка…», ошибка с «Повторить»,
  «Сессия без сообщений»; после загрузки — прокрутка к последнему сообщению.
  Живого обновления нет: загрузка при открытии таба и по общей кнопке
  «Обновить».
- Панель списка: закреплённый «Дом агента» (без меню действий), ниже — проекты
  (имя + кнопка «⋮» с меню действий: сейчас одно — «Удалить», меню расширяемое);
  в шапке панели заголовок «Воркспейсы» и кнопка «+» — создание проекта
  в модальном окне с двумя режимами: «Пустой проект» (поле имени, валидация
  slug) и «Из GitHub» (поле URL репозитория, поле имени выводится из URL и
  редактируется, статус токена, индикатор «Клонирование…», inline-ошибка; на
  409 `name-exists` владелец меняет имя).
- Секция «Git-доступ» в той же панели (под списком): статус GitHub-токена
  («токен задан» / «не задан»), кнопки «Задать/Заменить токен» и «Забыть
  токен»; ввод токена — в модальном окне, поле-пароль, значение после
  сохранения не показывается (как token Telegram). Статус перечитывается
  после сохранения/сброса.
- Дерево ленивое: раскрытие папки подгружает содержимое, папки первыми; пустые
  состояния — «Выберите воркспейс» и «Каталог пуст». При входе в раздел ничего
  не выбрано; последний выбор запоминается (localStorage) и восстанавливается.
- Удаление проекта: «⋮» → «Удалить» → модальное подтверждение в стиле админки
  (имя и путь проекта, «удаляется безвозвратно», кнопки «Удалить»/«Отмена»);
  нативный `confirm` не используется.
- Дерево живёт синхронно с каталогом: изменения воркспейса извне (владелец или
  серверные процессы правят файлы напрямую) доставляются push-событиями, UI
  перечитывает затронутые узлы.
- Страница «Модели» (новый пункт сайдбара, по образцу WorkspacesPage):
  карточки подключений провайдеров. Закреплённая карточка DeepSeek
  (официальный): статус ключа (маскирован «••••») и кнопка «Изменить ключ»,
  удаления нет; карточка модели не показывает — модели каталога движка (2)
  владелец видит в селекте «Дефолтная модель» (группа DeepSeek).
  Карточки остальных
  подключений — пресеты каталога движка (по
  каталоговому провайдеру; официальный URL по умолчанию, при override —
  baseURL) и «Свой URL» (custom): название/displayName, ключ
  «••••»/«не задан», чипы моделей, «⋮» → Изменить / Удалить (модальное
  подтверждение, как у проектов). Шапка страницы: селект «Дефолтная
  модель» (группы по подключениям: DeepSeek — модели каталога движка dsh
  (`deepseek-flash`, `deepseek-v4-pro`); дефолт свежего профиля движка
  0.2.1-rc.4 — `deepseek-flash` — входит в каталог, поэтому селект показывает
  текущий дефолт, а сохранение текущего дефолта не отвергается; pinned-список —
  только fallback при недоступности рантайм-каталога;
  пресеты и «Свой URL» — выбранные/введённые владельцем id) и кнопка
  «+ Добавить». Модалка
  «Добавить/Изменить»: селект «Провайдер» — список пресетов каталога
  движка (OpenAI, Anthropic, OpenRouter, Groq, Google, Mistral, xAI,
  Together, Cerebras, Fireworks, OpenCode) и пункт «Свой URL» (custom).
  У выбранного пресета — официальный URL по умолчанию, переключатель
  «свой URL» открывает поле baseURL (override); затем ключ и модели:
  при выборе провайдера форма запрашивает models.catalog и модели
  выбираются из каталога провайдера (поиск/чипы, минимум одна); ручной
  ввод — fallback. Пункт «Свой URL» — displayName, baseURL, ключ, модели:
  каталога нет — ввод вручную. DeepSeek официальный в селекте нет:
  он закреплённая карточка, редактируется только ключ. Валидация
  на клиенте и сервере. Пустое состояние (подключений кроме DeepSeek
  нет): «Добавьте провайдера с ключом».

- Страница «Telegram» — отдельный пункт сайдбара в том же dev-tool стиле:
  карточка состояния (`не настроено` / `выключено` / `подключено` / `ошибка`),
  поле token-пароля с маской `••••`, числовое поле Telegram User ID,
  чекбокс **«Включить бота»** и чекбокс **«Потоковый ответ»** — настройка
  потоковой доставки текста ответа в чат: включена по умолчанию, выключенная
  возвращает доставку финальным сообщением (длинный ответ приходит несколькими
  сообщениями). Переключатель «Потоковый ответ» уходит тем же сохранением, что
  остальные поля формы. Тут же username
  бота и время последнего polling. Кнопки:
  «Проверить подключение», «Сохранить», «Отключить», «Удалить токен»; удаление
  token требует модального подтверждения.
- Token никогда не возвращается API и не показывается после сохранения;
  сохранение без нового token оставляет старый. Включение без token или
  положительного User ID блокируется клиентской и серверной валидацией.
  Статус и безопасная ошибка обновляются после каждой операции без рестарта:
  страница перечитывает `telegram.status` после save/test/disable/clear-token,
  потому что переход runtime асинхронен и ответ `save` может показать ещё не
  запущенное подключение, а `disable`/`clear-token` — уже снятые настройки при
  цикле, дожидающемся текущего long poll.
- В Telegram UI владельцу доступны inline-список дом/проектов, lazy-дерево
  выбранного workspace и ограниченный просмотр text-файлов; админка не
  отображает Telegram message history и не управляет Telegram-сессиями.
- Страница «Память» (live-пункт сайдбара в группе «Управление») —
  самостоятельная страница управления долговременной памятью из трёх вкладок:
  «Записи», «Очередь ревью» и «Метрики». Нового пункта сайдбара вкладки не
  добавляют.
- Вкладка «Записи» — текущее содержимое страницы без изменений: селектор уровня
  («Дом» / проект из `workspaces.list` / «Все»; при исчезновении проекта — откат
  на «Дом»), строка поиска (FTS), фильтр типа, поле тега, тумблер «только
  пиннутые», «+ Добавить запись» и «Обновить». «Все» — режим просмотра: запрос
  уходит без фильтра scope, поэтому список показывает записи дома и всех
  проектов сразу. Плоский список: пиннутые
  сверху, затем по времени изменения; в строке — бейдж типа, бейдж уровня
  («Дом» или имя проекта), метка пиннинга,
  текст, чипы тегов, провенанс «владелец/агент · локальное время» и действия
  «Изменить»/«Удалить». Создание/правка — модалка (тип, текст, теги, пиннинг).
  Уровень: при создании из конкретного уровня показан неизменяемым контекстом,
  а в режиме «Все» выбирается в модалке (по умолчанию «Дом»); при правке
  показан уровень самой записи и не меняется (scope неизменяем);
  удаление — модальное подтверждение. Состояния: «Загрузка…», «Память пуста —
  добавьте первую запись», «Ничего не найдено», ошибка с «Повторить»; отказ
  `secret-detected` показывается inline в модалке. Серверного push для памяти
  нет: список перечитывается после каждой мутации и по «Обновить».
- Вкладка «Очередь ревью» (на ярлыке — счётчик ожидающих предложений; когда
  очередь не помещается в одну страницу, значение показывается с «+», например
  «500+»): строка
  политики, отрендеренная из ответа сервера, — «Владелец и явный `remember`
  пишут сразу; предложения пайплайна — через ревью. Автоодобрения нет»; тулбар —
  уровень («Дом» / проект из `workspaces.list` / «Все», тот же паттерн и откат на
  «Дом»), фильтр типа, поле тега, тумблер «Показать решённые» и «Обновить».
  Серверного push нет: очередь перечитывается после каждой мутации и по
  «Обновить».
- Строка очереди ревью: бейдж типа, бейдж уровня, текст предложения, чипы
  тегов, провенанс «предложено пайплайном · `originRef`» и время предложения; у
  решённых — бейдж «принято» / «принято с правкой», время решения
  и действий нет. Отклонённых строк в очереди не бывает: отказ удаляет
  предложение, поэтому в режиме «Показать решённые» видны только принятые, а
  исчезнувшее после отказа предложение можно предложить заново.
  Пайплайн в этой итерации — служебный ход извлечения (p10g),
  поэтому `originRef` выглядит как `<канал> session:<id>`; ярлык и разметка
  строки не меняются. У ожидающих два действия: «Одобрить» — модалка с
  предзаполненными типом, текстом, тегами и тумблером пиннинга (подтверждение
  отправляет патч), и «Отклонить» — модальное подтверждение; отдельной кнопки
  «Изменить и одобрить» нет — правка живёт внутри модалки одобрения.
- Состояния очереди ревью: «Очередь пуста», «Решённых предложений нет»,
  «Ничего не найдено», ошибка с «Повторить»; `secret-detected` при правке —
  inline в модалке, `invalid-status` — «Предложение уже решено» и перезагрузка,
  404 — перезагрузка (в т.ч. повторный отказ уже удалённого предложения).
- Вкладка «Метрики» (p10i) читает снимок `memory.metrics` и ничего не считает:
  показываются только документированные поля. Сводка — окно (начало,
  длительность, ходы, доставки), накопительные тоталы процесса, `recall`
  (вызовы, пустые, ошибки, средняя и максимальная латентность), промахи
  (доставлено, но не запрошено; сброшено сверх потолка id). Ниже — таблицы по
  каналам и уровням и топ записей по попаданиям (id, тип, уровень,
  ядро/карта/push, recall). Рядом с числами — объяснение сигнала: попадание,
  два промаха, а ошибка хранилища — деградация; снимок не содержит текста
  памяти. Обновление при открытии вкладки и по кнопке «Обновить»; живого опроса
  нет. «Сбросить окно» — вторичное действие с модальным подтверждением и
  пояснением, что закрывается только окно наблюдения, а накопительные тоталы
  процесса сохраняются; после сброса показывается закрытое окно с уведомлением.
  Состояния — «Загрузка…», ошибка с «Повторить», пустое окно с пояснением, что
  нули — сигнал, а не сбой; на `503 metrics-unavailable` вкладка объясняет, что
  сервис метрик не собран, а «Записи» и «Очередь ревью» работают как раньше.
  Клик по id записи переключает на «Записи» в режим «Все» и подсвечивает строку;
  если запись удалена, подсветки нет — список просто перечитывается.

## Target design v1

Утверждённый целевой визуальный контракт для всех существующих и будущих
экранов. Значения ниже — проектные, а не измерения текущей реализации; их
наличие в документе не означает, что они уже реализованы или проверены в
браузере.

### 1. Характер интерфейса

Админка — строгий рабочий инструмент разработчика с тёмной темой. Визуальный
характер: спокойный, точный, собранный; плотность умеренная, а не предельно высокая.
Презентабельность достигается читаемостью, выравниванием и согласованностью
компонентов, а не декором.

Синий обозначает действие, выбор и фокус, но не окрашивает весь интерфейс.
Зелёный, жёлтый и красный используются только по смыслу статуса. Большая часть
поверхностей остаётся нейтральной. Не используются декоративные градиенты,
«стекло», свечение, объёмные кнопки, иллюстрации-заполнители и пульсирующие статусы.

Один визуальный язык не означает одинаковую компоновку. Предусмотрены:

- **Стандартная плотность:** настройки, формы, подключение провайдеров, диалоги.
- **Компактная плотность:** дерево файлов, вкладки, рабочие панели, служебные строки.

Это варианты компонентов, а не новый пользовательский переключатель. Уменьшать
весь интерфейс через `zoom` или `transform: scale` нельзя. Свободное пространство
допустимо; его не заполняют вымышленными метриками или неподдерживаемыми функциями.

### 2. Цветовая система

Цвета задаются семантическими CSS-переменными. HEX-значения используются в
определении токенов, а не копируются по компонентам. Все цвета таблиц непрозрачны,
если явно не указано иное.

Внешняя загрузка шрифтов для этой версии дизайна не требуется. Кириллица и

моноширинными только из-за технического назначения продукта.

### 4. Отступы и геометрия

Базовая шкала отступов: **4, 8, 12, 16, 20, 24, 32, 40, 48, 64 px**.
Значение 2 px допускается для тонких визуальных маркеров и оптической коррекции,
но не создаёт отдельную шкалу межблочных расстояний.

| Связь элементов | Значение |
|---|---:|
| Иконка → подпись | 8 px |
| Между соседними кнопками | 8 px |
| Подпись поля → поле | 8 px |
| Поле → пояснение или ошибка | 4 px |
| Между группами полей | 20 px |
| Заголовок карточки → содержимое | 16 px |
| Внутри обычной карточки | 24 px |
| Внутри компактной карточки или на узком экране | 16 px |
| Между карточками одной группы | 16 px |
| Между самостоятельными секциями | 32 px |
| Заголовок страницы → первый блок | 24 px |
| Внешние поля обычной страницы | 32 px на широком экране; 24 px на среднем; 16 px на узком |

Скругления: 4 px для строки или компактного выделения, 8 px для кнопок и полей,
12 px для карточек, диалогов и меню. Полное скругление допускается у небольшого
статуса, чипа и переключателя, но не у каждой кнопки.

Граница — 1 px. Контур фокуса — 2 px с отступом 2 px. Карточки не имеют тяжёлой
тени. Меню: `0 8px 24px rgb(0 0 0 / 24%)`; диалог:
`0 16px 48px rgb(0 0 0 / 36%)`; подложка диалога:
`rgb(0 0 0 / 56%)` без размытия всей страницы.

### 5. Каркас и прокрутка

Основной каркас Main: сайдбар слева, топбар над содержимым, рабочая область под
ним. Высота топбара — 56 px. Полная ширина сайдбара — 224 px, компактная — 64 px.
Брендовый блок сайдбара выровнен по высоте топбара.

Пункты навигации имеют минимальную высоту 40 px, внешние поля панели — 12 px,
горизонтальные внутренние отступы пункта — 12 px. Иконка — 20 px, расстояние до
подписи — 8 px. Между группами навигации — 24 px. Выбор: `--bg-selected`,
основной текст и маркер 2 px; фокус обозначается отдельным контуром.

Топбар содержит текущий контекст и существующие глобальные действия. Названия,
статус сервиса и состояние конкретного подключения не объединяются в один
безымянный индикатор. Расположение управления аккаунтом не меняет сценарий выхода.

**Корневая страница Main не прокручивается.** Рабочая область занимает остаток
высоты вьюпорта под топбаром; каждая самостоятельная панель имеет свой скроллер.
На обычной странице настроек или списка это один скроллер основной области,
а не отдельный скроллер у каждой карточки. На «Проектах» независимо прокручиваются
список воркспейсов, дерево и содержимое активного правого таба; лента табов
остаётся на месте. Сайдбар прокручивается отдельно при нехватке высоты.

В реализации это предполагает ограниченную высоту корневого контейнера, корректные
`min-width: 0` / `min-height: 0` у вложенных flex/grid-элементов и осмысленные
границы `overflow`. Используется динамическая высота вьюпорта с подходящим
fallback. Прокрутка нигде не отключается без доступного внутреннего скроллера.

Обычные страницы имеют заметный заголовок. **«Проекты» — явное исключение:**
дополнительный h1 и вводный текст над рабочими панелями не добавляются; заголовок
и контекст остаются в топбаре, как в исходном описании.

### 6. Ширина и типы страниц

Все ширины в таблице относятся к области внутри основной навигации, а не ко всему
монитору. Ограничение ширины не означает вертикальное центрирование страницы.

| Тип | Целевая ширина и размещение |
|---|---|
| Настройки и интеграции | Колонка до 720 px, выравнивание по левому краю содержимого |
| Каталог подключений | Контейнер до 1200 px, сетка 1–3 колонки по доступной ширине |
| Память, очередь ревью и метрики | Колонка до 1120 px; текст записей не разносится на всю ширину большого монитора |
| Рабочая зона проектов | Полная доступная ширина, без внешней карточки вокруг панелей |
| Отрендеренный Markdown | Текстовая колонка до 960 px; таблицы и код имеют собственное переполнение |
| Транскрипт сессии | Колонка до 1120 px в правой зоне, выровненная по левому краю |
| Login | Карточка до 400 px; отступ от края окна не меньше 16 px |

Максимальная ширина не задаётся как минимальная. Заголовок, фильтры и список
одной страницы имеют общую линию выравнивания. На широком экране обычное содержимое
начинается от левого поля основной области; лишнее место справа допустимо.

Карточки провайдеров: минимальная желательная ширина 320 px, промежуток 16 px.
Если доступная ширина меньше 320 px, карточка занимает её целиком, не создавая
горизонтальный скролл. Число колонок определяется внутренней шириной контейнера,
а не только шириной окна.

### 7. Компоненты

#### Кнопки и иконки

| Вариант | Минимальная высота | Горизонтальные поля | Применение |
|---|---:|---:|---|
| Стандартная кнопка | 40 px | 16 px | Формы, действия страницы |
| Компактная кнопка | 32 px | 12 px | Рабочая панель, действие строки |
| Кнопка-иконка | 36 × 36 px | — | Меню, обновление, вспомогательное действие |
| Компактная кнопка-иконка | 32 × 32 px | — | Закрытие вкладки, дерево, плотный тулбар |
| Сенсорный режим | Область нажатия от 44 × 44 px | По содержимому | При `pointer: coarse` |

Иконки внутри обычных кнопок — 16 px, в навигации — 20 px. Используется один
набор и единая толщина линии около 1,75–2 px. Размер графики не равен размеру
области нажатия. Emoji не используются вместо системных пиктограмм.

Основная кнопка имеет синюю заливку. Вторичная — нейтральную поверхность,
читаемый текст и при необходимости границу. Малозначимое действие — без постоянной
заливки, но с явными состояниями наведения и фокуса. Удаление в строке —
спокойное текстовое действие или пункт меню; сплошная красная заливка прежде
всего у финального подтверждения.

В одном блоке действий — одно главное действие. Повторяющиеся действия каждой
строки не превращают весь список в набор ярких синих кнопок. Порядок в формах
и диалогах: отмена слева от основного действия; опасное действие отделено по смыслу.

Кнопка загрузки сохраняет ширину, показывает процесс и не отправляет повторный
запрос. Недоступность кнопки сопровождается понятной причиной там, где иначе
неясно, как продолжить.

#### Поля и переключатели

Поле и селект: минимальная высота 40 px, горизонтальные поля 12 px, радиус 8 px.
Фон `--bg-input`, текст `--text-primary`, placeholder `--text-muted`, граница
`--border-control`. Фокус добавляет внешний контур, не меняя геометрию поля.
Ошибка — красная граница и сообщение под полем, а не одна смена цвета.

Многострочное поле: минимальная высота 112 px, вертикальное изменение размера
там, где оно не разрушает компоновку. Подпись всегда остаётся над полем;
placeholder не заменяет подпись. В одном столбце не смешиваются разные высоты
полей без смысловой причины.

Визуальный флажок — 18 × 18 px, вместе с подписью образует область нажатия
не меньше 40 px по высоте. Переключатель — примерно 40 × 24 px, также внутри
строки высотой от 40 px. На сенсорном устройстве интерактивная область — от 44 px.

**Редизайн не меняет момент применения значения.** Флажок или переключатель,
который сейчас сохраняется общей кнопкой, не становится немедленным действием.
Различие между сохранением настройки и отдельной runtime-операцией сохраняется.

#### Карточки, списки и таблицы

Карточка: фон поверхности, граница 1 px, радиус 12 px, внутренние поля 24 px.
На узком экране поля 16 px. Заголовок и меню действий выровнены по верхней линии.
Обычная карточка без перехода или действия не получает «кликабельное» наведение.

Стандартная однострочная запись списка или таблицы — от 48 px. Строка с названием
и метаданными — от 56 px, типично 64 px. Строка дерева — 32 px. Высота содержательных
записей памяти и ревью автоматическая: текст не обрезается ради одинаковых карточек.

Ячейки таблицы: внутренние отступы 12 px по вертикали и 16 px по горизонтали;
компактный вариант — 8 и 12 px. Таблицы применяются только к табличным данным,
а не принудительно ко всем существующим спискам.

Длинные имена в навигации и вкладках допускают многоточие с доступом к полной
подписи. Содержимое записи, сообщение об ошибке и последствия удаления не
обрезаются многоточием. Полный путь и идентификатор остаются доступными для чтения
и копирования; tooltip не является единственным способом получить важные данные.

#### Вкладки и рабочие разделители

Лента вкладок — от 44 px по высоте. Подпись — 14/20 px. Активная вкладка отличается
текстом, фоном и нижней линией 2 px. Клавиатурный фокус — отдельный контур.
Динамическая вкладка обычно занимает 120–240 px; её название может сокращаться.
Вкладка «Сессии» имеет ширину по содержимому и не получает кнопку закрытия.

Для страницы «Проекты» эта лента является основным навигационным механизмом
правой рабочей области: закреплённый «Сессии» + динамические табы открытых сессий
и файлов. Она не заменяется постоянными категориями `Сессии / Файлы / Настройки`
и не дублируется вторым уровнем вкладок над содержимым.

Закрытие — отдельная кнопка 32 × 32 px, не вложенная в кнопку активации. Лента
прокручивается горизонтально без горизонтальной прокрутки всей страницы.
Названия файлов и сессий остаются различимыми; текущие `title`-подсказки сохраняются,
при необходимости дополняются доступным способом показать полный текст.

Видимый разделитель панелей — 1 px, область захвата мышью — 8 px. Изменение
размера должно иметь клавиатурный или кнопочный эквивалент. На узких и сенсорных
экранах доступ к панелям обеспечивают явные кнопки, а не обязательное точное
попадание в разделитель.

#### Статусы, чипы, меню

Статус или чип — от 24 px по высоте, текст 12/18 px, горизонтальные поля 8 px.
Интерактивный чип имеет область нажатия от 32 px, на сенсорном устройстве — от 44 px.
Большое число чипов переносится по строкам; название модели или тег нельзя
обрезать так, чтобы невозможно было различить значения.

Меню: фон `--bg-elevated`, радиус 12 px, поля контейнера 8 px, пункт от 36 px.
Оно не выходит за края окна и доступно с клавиатуры. Опасный пункт отделяется
от обычных, когда в меню есть оба типа действий.

#### Диалоги

Ширины: подтверждение — до 440 px; обычная форма — до 560 px; сложная форма
подключения — до 720 px. Максимальная ширина всегда ограничена окном минус
32 px. Внутренние поля — 24 px, на узком экране — 16 px.

Максимальная высота — высота динамического вьюпорта минус 48 px на десктопе
и минус 32 px на узком экране. Если содержимое длинное, прокручивается тело
диалога; заголовок и действия остаются доступными. При экранной клавиатуре
поля и кнопки не должны оказаться вне доступной области.

Диалог имеет заголовок и управляемый фокус; после закрытия фокус возвращается
к вызвавшему элементу [A5]. Удаление показывает конкретный объект и реальные
последствия. Отмена ничего не изменяет. Нативный `confirm` не вводится.
Случайный клик по фону не должен молча терять несохранённую форму.

### 8. Применение к описанным экранам

Эта секция задаёт внешний вид, но не заменяет функциональные детали `Current state`.
Новые страницы используют те же типы компоновки и компоненты, даже если ещё
не перечислены в предоставленном описании.

#### Login

Одна карточка шириной до 400 px: бренд, заголовок, существующие поля, inline-ошибка
и основная кнопка шириной карточки за вычетом полей. Внешняя область — фон приложения.
На достаточной высоте карточка центрируется; на низком экране становится доступной
через прокрутку контейнера Login. Состав полей и схема авторизации не меняются.

#### WorkspacesPage / «Проекты»

Сохраняются три рабочие колонки под топбаром: список воркспейсов, дерево, правая
зона табов. Сайдбар приложения находится вне этих трёх колонок. Дополнительная
верхняя карточка, дублирующий h1 и переключатель «Файлы / Сессии» вместо
существующей рабочей модели не добавляются.

**Инвариант правой рабочей области:** правая колонка является IDE-подобным
tab workspace, а не страницей проекта с постоянными разделами.

- Первый таб всегда — закреплённый и незакрываемый «Сессии». Его содержимое —
  список сессий выбранного воркспейса.
- Открытие конкретной сессии создаёт или активирует динамический таб с названием
  этой сессии.
- Открытие файла из дерева создаёт или активирует динамический таб с именем файла.
- Одновременно допустима последовательность вида
  `Сессии | Сессия A × | BACKLOG.md × | send_telegram.py ×`.
- «Файлы», «Настройки» и другие сущности не добавляются как постоянные табы
  верхнего уровня только ради редизайна. Файлы открываются из дерева в динамических
  табах.
- Внутри правой колонки не добавляется постоянный заголовок проекта, отдельная
  карточка проекта или второй уровень навигации над tab bar: рабочая область
  начинается с существующей ленты табов.
- Действие «Обновить» остаётся справа в плашке tab bar и не прокручивается вместе
  с лентой динамических табов.
- При редизайне разрешено менять размеры, отступы, цвета, active/hover/focus,
  оформление `×`, горизонтальную прокрутку и визуальные разделители tab bar,
  но не его информационную архитектуру и поведение.

Таким образом, содержимое правой зоны всегда определяется активным табом:
список сессий, транскрипт конкретной сессии либо содержимое файла. Отдельный
постоянный toolbar с поиском, фильтрами или действиями не добавляется над всеми
типами содержимого; такие элементы допустимы только внутри конкретного таба,
если соответствующая функция отдельно предусмотрена продуктовым контрактом.

На полном десктопе: список воркспейсов 240 px; дерево по умолчанию 280 px,
допустимый диапазон 220–480 px; правая область получает остаток и сохраняет
не меньше 480 px. Максимум дерева дополнительно ограничен фактически доступной
шириной. Все максимумы не обязаны помещаться одновременно.

Шапки панелей — 44 px. Строка воркспейса с именем и путём — от 56 px. Дерево —
32 px на строку, отступ уровня 16 px, технический текст 13/20 px. «Дом агента»
остаётся закреплённым и без проектного меню. «Git-доступ» остаётся под списком;
его перенос в другой раздел не входит в этот дизайн.

Сессии представлены строками с названием и компактно сгруппированными каналом и
локальным временем создания. При нехватке ширины метаданные переходят на вторую
строку под названием. Новейшие остаются сверху. Превью сообщений, сортировка по
последней активности и создание сессии не добавляются без отдельного контракта.

Файлы и сессии открываются в существующих динамических табах. Правила повторного
открытия, закрытия, выбора соседнего таба и сброса UI-локального состояния не
меняются. Смена воркспейса, уход со страницы и перезагрузка по-прежнему сбрасывают
табы согласно исходному описанию. Само изменение ширины или видимости панели
не является новым основанием для сброса.

В транскрипте сохраняются метки ролей, `pre-wrap`, свёрнутые служебные `<details>`
и пометка «не в контексте». Приглушается именно пометка, а не вся реплика до
нечитаемого состояния. Между репликами — 20 px, между ролью и текстом — 8 px.
Служебный summary — от 32 px по высоте и с явным маркером раскрытия.

Файл: отступы области чтения 24 px, на узком экране 16 px. Markdown рендерится
в читаемом текстовом стиле; исходник и код — моноширинные. Переключатель
«Просмотр / Исходник», предупреждение о лимите и состояния неподдерживаемого
содержимого остаются видимыми. Строки кода не разрываются ради ширины окна;
при необходимости прокручивается кодовый блок, а не вся админка.

#### ModelsPage / «Модели»

Заголовок страницы и действие «Добавить» образуют верхний уровень. Селект
«Дефолтная модель» расположен отдельной понятной строкой или в верхнем блоке
управления, но не сжимается до нечитаемой ширины ради размещения рядом с заголовком.
Существующая модель сохранения выбора не меняется.

Подключения представлены сеткой карточек. Название провайдера — 16/24 px,
статус ключа — 12/18 px, URL и технические значения — моноширинные. Чипы моделей
переносятся. Меню находится в правом верхнем углу. Закреплённый DeepSeek сохраняет
особые действия и ограничения, описанные в `Current state`; редизайн не делает
его обычной удаляемой карточкой.

Формы используют общие поля, секции и диалоги. Источник каталога, доступные модели,
пресеты, overrides и fallback ручного ввода не переопределяются дизайном.

#### TelegramPage / «Telegram»

Контент ограничен 720 px. Вверху — название страницы. Карточка состояния содержит
реальное состояние подключения, username и время последнего polling. Общий статус
сервиса в топбаре не подменяет состояние бота.

Проверка подключения визуально относится к состоянию соединения. Настройки токена,
Telegram User ID и включения сгруппированы в форме. Сохранение — основное действие
формы, «Отключить» — отдельная вторичная операция, «Удалить токен» — отдельная
нижняя опасная секция с существующим модальным подтверждением.

Флажок/переключатель включения и «Отключить» не объединяются без подтверждённого
изменения функционального контракта: исходный документ описывает обе операции.
Проверка не должна незаметно менять объект тестирования — сохранённые или
редактируемые настройки; это определяется действующим контрактом, а не стилями.

Сохранённый токен не раскрывается. Поле нового токена остаётся полем-паролем
с понятным пояснением о сохранении текущего значения при пустом вводе. Статус
«Токен сохранён» допустим только при наличии соответствующих безопасных данных.
Удаление не имитируется очисткой поля.

Асинхронный runtime-переход отображается как процесс, если это подтверждается
данными; «Подключено» не появляется оптимистически сразу после save. Повторное
чтение `telegram.status` после операций сохраняется. Отдельные новые проверки
или изменения polling эта спецификация не вводит.

#### MemoryPage / «Память»

Сохраняются вкладки «Записи», «Очередь ревью» и «Метрики», а не отдельные пункты
сайдбара.
Заголовок, вкладки, фильтры и список имеют общий левый край и ограничение 1120 px.

На широком экране фильтры выстраиваются в один или два аккуратных ряда. Промежуток
между контролами — 12 px. Поиск получает гибкую ширину, а короткие селекты не
растягиваются на весь ряд. При сужении поля переносятся, сохраняя видимые подписи;
не появляется горизонтальная прокрутка всего тулбара.

Запись или предложение — содержательная строка с отступами 16 px: сверху тип,
уровень и состояние, ниже текст, затем теги и происхождение. Действия находятся
справа на широком экране и после содержимого на узком. Текст записи не скрывается
ради фиксированной высоты. Пиннинг и происхождение остаются различимыми.

Строка политики очереди получает спокойный информационный блок, но её текст
по-прежнему приходит с сервера. Счётчик и суффикс «+», состояния решений,
неизменяемость scope, фильтры и поведение отклонённых предложений сохраняются.
«Одобрить» открывает существующую форму правки; новая конкурирующая кнопка
«Изменить и одобрить» не появляется.

Вкладка «Метрики» — экран поверх готового снимка p10h: показывает уже собранное и
сама ничего не считает. Состав: сводка окна (начало и длительность, ходы,
доставки), накопительные тоталы процесса с их началом, `recall` (вызовы, пустые,
ошибки, средняя и максимальная латентность), число невостребованных доставок и
сброшенных id, разбивка по каналам (`admin`, `telegram`) и по scope, топ записей
по попаданиям (id, тип, уровень, попадания в ядро/карту/push,
`recallDelivered`/`recallQueries`).

Экран объясняет сигнал рядом с числами: попадание — запись доставлена в контекст
или выдана `recall`; промах — пустой `recall` (пробел в памяти) и запись,
доставленная и ни разу не запрошенная за окно (балласт); ошибка хранилища —
деградация, а не промах. Снимок не содержит текста памяти, поэтому экран явно
говорит, что показывает счётчики, а не содержимое записей; id записи — ссылка на
её строку во вкладке «Записи», если запись ещё существует.

Обновление — по кнопке «Обновить» и при открытии вкладки; живого опроса нет,
потому что серверного push для памяти не существует. «Сбросить окно» —
вторичное действие с модальным подтверждением и пояснением, что закрывается
только окно наблюдения, а накопительные тоталы процесса сохраняются.

Состояния: «Загрузка…», ошибка с «Повторить», пустое окно (счётчики нулевые —
это сигнал, а не сбой). На `503 metrics-unavailable` вкладка объясняет, что
сервис метрик не собран, и остаётся читаемой; вкладки «Записи» и «Очередь ревью»
при этом работают как раньше.

### 9. Адаптивность

Это **новое правило**, а не описание существующей реализации.
Ширины — CSS px окна браузера. Они меняют представление панелей, но не набор
функций, права доступа и серверные операции.

| Ширина окна | Навигация | Обычные страницы | «Проекты» |
|---|---|---|---|
| От 1280 px | Сайдбар 224 px | Поля 32 px от 1440 px, иначе 24 px | Список 240 px; дерево 280 px по умолчанию; правая зона от 480 px |
| 1024–1279 px | Компактная панель 64 px | Поля 24 px | Список 220 px; дерево 240 px по умолчанию; правая зона от 480 px |
| 768–1023 px | Компактная панель 64 px | Поля 24 px | Список воркспейсов открывается панелью поверх содержимого; дерево 240 px; правая зона от 420 px |
| Менее 768 px | Меню по явной кнопке | Поля 16 px; формы в один столбец | Одна основная зона; список воркспейсов и дерево открываются отдельно по кнопкам |

В диапазоне 1024–1279 px максимальная ширина дерева уменьшается, если иначе
правая зона станет уже 480 px. В диапазоне 768–1023 px дерево также может
сворачиваться; при недостатке места приоритет у читаемого активного содержимого.
Ни в одном режиме сумма минимальных размеров не выталкивает страницу за окно.

Компактная навигация использует узнаваемые иконки, доступные названия и подсказки
на наведении/фокусе; явное раскрытие показывает текстовые подписи. Кнопки
«Воркспейсы» и «Файлы» на узком экране открывают соответствующие панели, а не
заменяют текущую систему правых табов.

Открытие и закрытие адаптивной панели не меняет выбранный воркспейс и активный
таб. Существующее поведение при фактической смене воркспейса сохраняется.

Базовые проверки: 1920, 1440, 1280, 1024, 768, 390 и 320 px, а также увеличение
масштаба браузера. Для обычного текста и форм при 320 CSS px не требуется
горизонтальная прокрутка. Для содержимого с необходимой двумерной структурой,
например таблицы или кода, допускается прокрутка собственного контейнера [A4].
На низких экранах проверяется доступность действий без фиксированных пустых областей.

### 10. Состояния и обратная связь

Для существующих операций предусматриваются default, hover, pressed, selected,
focus, disabled и loading там, где состояние применимо. Выбор объекта не
совпадает с клавиатурным фокусом.

Начальная загрузка занимает место ожидаемого содержимого: спокойная надпись
или skeleton без декоративной пульсации. При обновлении уже загруженные данные
не исчезают без необходимости. Пока запрос не завершён, прошлый успешный
результат не выдаётся за подтверждение новой операции.

Пустое состояние содержит короткий заголовок и пояснение, а действие — только
если оно уже поддерживается. «Нет данных» и «Ничего не найдено» различаются.
Ошибка рядом с блоком предлагает существующую повторную попытку. Ошибка поля
остаётся рядом с полем до исправления; важная ошибка не показывается только
быстро исчезающим уведомлением.

Сохранение и удаление подтверждаются только после успешного результата. Успех
может показываться коротким уведомлением, но актуальное состояние также видно
в самом интерфейсе. Длительные операции имеют текстовый статус. Прогресс в
процентах показывается только при наличии реального источника значения.

Не вводятся новые автосохранение, live-обновление, фоновая проверка или постоянное
хранение состояния вкладок. Различие push дерева и ручного обновления транскрипта,
файла и памяти сохраняется согласно `Current state`.

### 11. Доступность и движение

Для обычного текста, включая placeholder и вспомогательные подписи, целевой
контраст — не менее 4.5:1 [A1]. Для значимых нетекстовых границ и индикаторов —
не менее 3:1 с прилегающей поверхностью [A2]. Декоративная рамка карточки не
обязана быть такой же яркой, как граница поля.

Проектный минимум области нажатия — 32 px в компактном десктопном интерфейсе,
обычно 36–40 px, и 44 px для сенсорного режима. Это собственный выбор дизайна;
он не объявляется буквальным требованием WCAG, где критерий 2.5.8 задаёт 24 × 24
CSS px с исключениями [A3]. Маленькая область захвата разделителя компенсируется
доступным способом управления без точного перетаскивания.

У полей есть связанные подписи, у кнопок-иконок — доступные названия. Скрытый
текст не заменяется одной иконкой или цветом. Полный критичный текст доступен
не только при наведении мыши. Порядок Tab соответствует визуальному порядку.
Вкладки, меню и диалоги имеют корректную клавиатурную модель; модальный диалог
удерживает фокус внутри и возвращает его после закрытия [A5].

Индикаторы фокуса не обрезаются `overflow` соседнего контейнера. Sticky-панели
не закрывают активное поле. Проверяется увеличение текста/масштаба до 200%,
дополнительно — перекомпоновка при 320 CSS px [A4]. Это критерии приёмки дизайна,
а не декларация уже достигнутого соответствия всему WCAG.

Переход цвета — 120 ms ease-out; появление меню или диалога — до 160 ms без
пружины и заметного масштабирования. Декоративное движение отключается при
`prefers-reduced-motion`. Анимация не задерживает доступ к действию и не
подменяет сообщение о состоянии.

### 12. UI-копия

Язык интерфейса — русский; терминология берётся из существующего канона.
Названия «Проекты» в навигации, «Воркспейсы» в рабочей панели и «Дом агента»
не унифицируются автоматически: изменение терминов требует отдельного решения.

Кнопка называет действие: «Сохранить», «Проверить подключение», «Добавить запись»,
«Удалить». Для опасной операции в подтверждении называется объект. Существующие
предметные различия «Удалить токен» и «Забыть токен» не стираются без проверки.

Локальное время отображается единообразно. Для обычной строки допустимо
`01.10.2026, 00:08`, для технического статуса polling — с секундами. Уменьшение
точности отображения не меняет смысл timestamp: время создания сессии не
становится временем последней активности. Значения примеров не являются
данными реального приложения.

Не используются неопределённые сообщения «Что-то пошло не так», если доступна
безопасная конкретная причина. Ошибка не содержит токенов, ключей и служебных
секретов. Документ не определяет новые API-коды и тексты серверных политик.

### 13. Приёмка визуальной системы

Редизайн считается применённым к конкретному представлению, когда оно использует
общие токены, сохраняет свои действия и проверено на реальном содержимом и
характерных состояниях. Унаследовать CSS недостаточно для статуса «проверено».

Проверяются все существующие страницы, вкладки и диалоги, а не только показанные
на исходных скриншотах. Минимально по предоставленному описанию: Login, воркспейсы,
создание пустого проекта и клонирование, Git-токен, подтверждение удаления,
список и транскрипт сессий, типы просмотра файлов, модели и формы подключений,
Telegram и удаление токена, записи памяти, очередь ревью и их модальные формы.
Этот перечень не утверждает, что в репозитории нет других экранов.

Приёмка включает длинные имена и пути, ошибки, пустые списки, большое количество
вкладок и чипов, узкий экран, клавиатуру и масштабирование. Цвета проверяются
по фактическим стилям, а не только по скриншоту. Проверка нескольких цветовых
пар не заменяет проверку всех состояний.

Функциональные операции проверяются без изменения реальных секретов, рабочего
бота и production-данных. Дизайн сам по себе не является основанием для смены
зависимостей, архитектуры или серверных контрактов.

## Rules & invariants

- Смена общего направления — сначала изменение канона, затем реализация
  (`canon-first`). Утверждение визуального контракта не является разрешением
  менять код в том же заходе.
- Цвета, размеры, отступы и компоновка из `Target design v1` — визуальный
  контракт. `Current state` описывает реализованное состояние, поэтому
  расхождение кода с этими значениями — задача реализации, а не другое правило.
- Корневая страница Main не прокручивается. Каждая самостоятельная панель имеет
  свой скроллер; на обычной странице это один скроллер основной области. Дерево,
  список воркспейсов и активный правый таб прокручиваются независимо.
- Рабочая зона проектов сохраняет три колонки под топбаром на полном десктопе,
  незакрываемые «Сессии», динамические табы и их существующий жизненный цикл.
  Адаптивные представления меняют доступ к панелям, но не сущности и операции.
- Смена воркспейса, уход со страницы и перезагрузка продолжают сбрасывать табы
  согласно `Current state`. Постоянное хранение открытых табов не вводится.
- Источники данных, порядок записей, правила повторного чтения и ограничения
  редактирования не меняются ради визуального единообразия. Не добавляются
  автосохранение, автопроверки, live-обновление или вымышленные показатели.
- Git-доступ остаётся в панели воркспейсов; функции управления токенами и
  особенности закреплённых сущностей сохраняются. Перенос между разделами
  или объединение операций требует отдельного решения.
- Секреты не раскрываются. Редизайн не требует их чтения API, сохранения в новом
  клиентском хранилище или вывода в логи. Проверки не меняют production-данные.
- Рендер файлов остаётся клиентским поверх `WorkspaceFileResult`. Markdown
  санитизируется на клиенте, сырой HTML и скрипты не исполняются. Неизвестный
  тип имеет безопасный фолбэк на моноширинный текст. Лимиты чтения не меняются.
- Новые экраны используют общие токены и подходящий шаблон. Произвольные размеры
  не добавляются локально там, где уже определён соответствующий компонент.
- Любое противоречие с функциональным каноном разрешается отдельным изменением
  соответствующего документа, а не скрытой коррекцией под видом редизайна.

## Key details

- Дизайн-токены и вёрстка живут в `src/styles.css` (переменные `:root`);
  экранная структура — компоненты `src/components/*` и `src/pages/*`.
- UI-тексты — русские строки прямо в компонентах (без i18n-слоя на текущем
  этапе).
- Тип рендера определяется на клиенте по расширению пути (markdown — `.md`/
  `.markdown`; код — карта расширений на языки подсветки) и shebang для файлов
  без расширения; неизвестный тип — фолбэк на моноширинный текст.
- Токены `Target design v1` внедряются через существующие переменные и общие
  компоненты. Названия семантические; сопоставление с текущими переменными
  требует изучения кода.
- Дополнительная UI-библиотека, внешняя загрузка шрифтов и отдельный
  дизайн-сервис не являются требованиями этого контракта.
- Общие размеры контролов представлены вариантами «стандартный» и «компактный»;
  компоненты не получают произвольные размеры на каждой странице.
- Проверка палитры в `Target design v1` выполнена расчётом непрозрачных пар
  sRGB. Визуальная и функциональная проверка действующего приложения при
  утверждении не проводилась.

## Open questions

- Внедрение: какие представления уже приведены к `Target design v1`, какие
  проверены в браузере, а какие ещё нет — фиксируется по результату проверки.
- Прозрачность, изображения под текстом и производные состояния требуют
  перепроверки контраста; таблица расчётов не утверждает соответствие всего
  приложения WCAG.
- В `styles.css` есть ссылка на макет `mockups/admin-design-preview.html`,
  которого нет в репозитории: восстановить макет-референс или убрать ссылку?
- Какой набор настроек проверяет «Проверить подключение» на странице Telegram —
  уточняется из функционального контракта перед изменением расположения действия.
- Функции, не раскрытые в `Current state`, дизайном не определяются: новый
  экран или новое действие требуют отдельного продуктового решения.
