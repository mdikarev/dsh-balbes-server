# Admin UI

## Purpose

Зафиксировать общее направление внешнего вида админки `dsh-balbes-admin`: стиль
и дизайн как живой SoT направления. Дизайн полностью ещё не определён, поэтому
записи намеренно нестрогие — направление, а не пиксельный контракт. Детальные
правила появятся по мере дозревания дизайна.

## Scope

- Покрывает: общее стилевое направление (тема, характер типографики, компоновка),
  структуру экранов на уровне внешнего вида, язык UI-копии.
- Вне scope: точные токены/значения (цвета, отступы, шрифты), сетка и
  breakpoints, контракты доступности — фиксируются позже.
- Функциональные контракты админки (экраны Login/Main, JWT в localStorage,
  401 → logout, кнопка тестового промпта) — в ARCHITECTURE.md / OVERVIEW.md;
  термины — в GLOSSARY.md. Здесь — только «как это выглядит».

## Current state

Общее направление задаёт текущая реализация (`dsh-balbes-admin`):

- Тёмная dev-tool тема: тёмный фон, поверхности-карточки, светлый текст —
  «рабочий инструмент разработчика», без декоративности.
- Акцентный синий для действий и состояний; сдержанная служебная палитра
  (успех/ошибка); скругления умеренные.
- Моноширинный шрифт для «технического»: имя/бренд, код, ответы модели
  (терминальный бокс над кнопкой).
- Компактная функциональная компоновка: сайдбар + топбар + рабочая область;
  два состояния — экран входа (Login) и основная страница (Main).
- UI-копия на русском, короткая и точная.
- Реализация-референс: `packages/frontend/dsh-balbes-admin/src/styles.css`
  (токены в `:root`), компоненты `Brand`/`Sidebar`/`Topbar`, страницы
  `Login`/`TestPage`/`WorkspacesPage`.
- Страница воркспейсов («Проекты» в сайдбаре) — рабочая зона в три колонки под
  топбаром (h1 и пояснение страницы не выводятся; заголовок — в топбаре):
  панель списка воркспейсов (фикс. узкая), содержимое выбранного воркспейса —
  дерево каталогов/файлов (~1/3 остатка), правая пустая зона (зарезервирована
  под будущее содержимое, шапки нет). Разделитель дерево/правая зона
  перетаскиваемый.
- Панель списка: закреплённый «Дом агента» (без меню действий), ниже — проекты
  (имя + кнопка «⋮» с меню действий: сейчас одно — «Удалить», меню расширяемое);
  в шапке панели заголовок «Воркспейсы» и кнопка «+» — создание проекта
  в модальном окне (поле имени, валидация slug).
- Дерево ленивое: раскрытие папки подгружает содержимое, папки первыми; пустые
  состояния — «Выберите воркспейс» и «Каталог пуст». При входе в раздел ничего
  не выбрано; последний выбор запоминается (localStorage) и восстанавливается.
- Удаление проекта: «⋮» → «Удалить» → модальное подтверждение в стиле админки
  (имя и путь проекта, «удаляется безвозвратно», кнопки «Удалить»/«Отмена»);
  нативный `confirm` не используется.
- Дерево живёт синхронно с каталогом: изменения воркспейса извне (владелец или
  серверные процессы правят файлы напрямую) доставляются push-событиями, UI
  перечитывает затронутые узлы.
- Страница «Модели» (новый пункт сайдбара, по образцу WorkspacesPage):
  карточки подключений провайдеров. Закреплённая карточка DeepSeek
  (официальный): ключ маскирован «••••», кнопка «Изменить ключ», удаления
  нет. Карточки custom-подключений: displayName, baseURL, ключ
  «••••»/«не задан», чипы моделей, «⋮» → Изменить / Удалить (модальное
  подтверждение, как у проектов). Шапка страницы: селект «Дефолтная
  модель» (группы по подключениям: DeepSeek — закреплённый официальный
  список моделей каталога dsh 0.1.2-rc.1 (`deepseek-v4-flash`,
  `deepseek-v4-pro`), ре-синк при обновлении движка; custom — введённые
  id) и кнопка «+ Добавить». Модалка «Добавить/Изменить» двух видов:
  DeepSeek — только поле ключа; OpenAI-совместимый —
  displayName, baseURL, ключ, модели (ввод по одному, минимум одна);
  валидация на клиенте и сервере. Пустое состояние (нет custom-
  подключений): «Добавьте провайдера с ключом».

## Rules & invariants

- Смена общего направления (темы, палитры, компоновки) — изменение поведения
  продукта: сначала правится эта секция (canon-first), затем код.
- Текущий CSS — референс направления, но не сам контракт: конкретные значения
  в канон не переносятся, пока дизайн не дозреет.
- Новые экраны/страницы следуют зафиксированному направлению, пока секция не
  изменена.

## Key details

- Дизайн-токены и вёрстка живут в `src/styles.css` (переменные `:root`);
  экранная структура — компоненты `src/components/*` и `src/pages/*`.
- UI-тексты — русские строки прямо в компонентах (без i18n-слоя на текущем
  этапе).
