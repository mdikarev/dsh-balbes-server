# Сессии воркспейса из Telegram — дизайн

- Status: approved design
- Date: 2026-09-19
- Инициатива: `docs/canon/future_plans/p5-telegram-sessions.md`

## Цель

Владелец управляет сессиями воркспейса прямо из чата с ботом: `/reset` начинает
новую сессию, не уничтожая прежние, а `/sessions` показывает сессии активного
воркспейса и возвращает к любой из них штатным resume. Список не растёт
бесконечно: ненужную сессию можно убрать в архив и при желании вернуть оттуда.

Инициатива завершает линию p1–p3: реестр сессий воркспейса и витрина в админке
уже есть, но из канала владелец видит и продолжает ровно одну persistent-сессию
на воркспейс, а `/reset` её «удаляет». Этот шаг даёт каналу модель «новый чат +
список прежних».

## Решения и границы

- **Модель «новый чат + список».** `/reset` отсоединяет живой хэндл и очищает
  активную привязку — ровно как сегодня в движке — но прежняя сессия остаётся в
  реестре и на диске и доступна для возврата. Ничего не удаляется: persistence
  движка не имеет API удаления («Nothing deletes session files»,
  `dsh-session-persistence-jsonl`), а реестр append-only.
- **`/reset` неразрушающий, отдельной `/new` нет.** Раз `/reset` лишь начинает
  новую сессию, он и есть действие «новая сессия»; отдельная команда-синоним не
  вводится. Меняется только обещание в текстах: сейчас `/reset` обещает
  «сессия удаляется», станет «прежняя остаётся в /sessions».
- **`/sessions` — список и возврат.** Показывает сессии активного воркспейса из
  реестра (канал `telegram`), отмечает активную, возвращает выбранную через
  штатный resume.
- **Архив.** Сессию можно убрать в архив (скрыть из активного списка) и вернуть
  обратно; архивный признак — канальное свойство в `telegram-state.json`.
  Архив активной сессии отсоединяет её и очищает активную привязку (как `/reset`,
  но с попаданием в архив). Архивные сессии остаются в реестре, на диске и
  видны в режиме «Архив».
- **Источник принадлежности — реестр воркспейса `workspace-sessions.json`.**
  Реестр не меняется: остаётся append-only, upsert по `sessionId`, канал
  `telegram`. Удаления в реестр не добавляются.
- **Активная сессия и архив — в `$DSH_HOME/telegram-state.json`.** Поле
  `sessions[воркспейс]` уже означает «активная сессия воркспейса»; добавляется
  опциональное поле `archived[воркспейс] = [sessionId, …]`. Версия документа
  остаётся 1, старый файл без `archived` грузится как пустой архив.
- **Определение заголовка/времени/доступности — из движка**, как в админке:
  `sessionQuery.readTitleSnapshots`. Сессия, которую движок уже не читает,
  помечается недоступной и не выбирается (но её можно архивировать).
- **Контеймент — по активному воркспейсу.** Список содержит только сессии
  выбранного воркспейса; возврат к сессии другого воркспейса — сначала `/ws`.
  Выбор сессии активный воркспейс не меняет.
- **Выбор сессии во время задачи запрещён.** Если по воркспейсу выполняется
  задача или есть очередь, `ses:<i>` отвечает «Дождитесь завершения или /stop».
  Сам `/reset` сохраняет прежнее поведение (прерывает turn, как сейчас).
- **Область — только Telegram.** Админка управление не получает: её таб
  «Сессии» остаётся чтением. HTTP-поверхность `/api/*` не меняется.
- Вне границ: удаление/переименование сессий; очистка истории; возврат к сессии
  другого воркспейса одним шагом; поиск/экспорт; ветвление и компактация;
  streaming; мультивладелец и другие каналы.

## Архитектура

### Состояние канала — `packages/plugins/dsh-balbes-telegram/src/state.ts`

- `TelegramStateData` расширяется опциональным
  `archived?: Record<string, string[]>` (ключи воркспейсов — те же
  `home` / `project:<имя>`).
- `assertShape` учит поле: `archived` — объект; значения — массивы непустых
  строк без дублей; пустые массивы нормализуются в отсутствие ключа. Проверка
  применяется и на load, и на save, как для остальных полей, поэтому
  невалидная запись не роняет стор, а отвергается до записи.
- Версия остаётся `1`; старый документ без `archived` читается как пустой
  архив. Миграции не требуется.
- `load()` по ENOENT по-прежнему отдаёт `{version: 1, sessions: {}}`.

### Обвязка канала — `packages/plugins/dsh-balbes-telegram/src/index.ts`

- `live` дополняется `archived`; `persist()` включает непустой `archived` в
  снимок; запись остаётся сериализованной через `saveChain`.
- `SessionsRegistryLike` расширяется чтением:
  `list(ref): Promise<Array<{sessionId: string; channel: string}>>`.
- Добавляется необязательный срез движка
  `sessionQuery?: { readTitleSnapshots(ids): Promise<TitleObservation[]> }`
  (читается через `ctx.get` как остальные необязательные сервисы; его
  отсутствие деградирует список, а не роняет канал).
- Собирается канал-специфичный срез `sessions`:
  - `list(ref): Promise<ChannelSessionRow[]>` — записи реестра с
    `channel === "telegram"`, соединённые с `readTitleSnapshots`
    (заголовок, время, доступность) и с `archived` из `live`; сортировка —
    новейшие первыми (по времени движка; без `sessionQuery` — обратный порядок
    реестра). Форма строки:
    `{id, title: string | null, createdAt: string | null, available: boolean, archived: boolean, active: boolean}` (`active` — совпадает с активной привязкой воркспейса).
  - `select(ref, sessionId)` — `selectSession` (см. ниже).
  - `archive(ref, sessionId)` — добавляет id в `live.archived` и `persist()`;
    если id был активным, вызывается `runner.reset(ref)` и активная привязка
    очищается.
  - `unarchive(ref, sessionId)` — убирает id из `live.archived` и `persist()`;
    активная привязка не меняется.
- Обёртка раннера `runnerWithSessions` получает `selectSession(ref, sessionId)`:
  отсоединяет текущий хэндл (`runner.reset(ref)`), записывает
  `live.sessions[key] = sessionId`, `persist()`; следующая задача резюмит
  выбранную. Дополнительно `sessionIdOf(ref)` возвращает
  `runner.sessionIdOf(ref) ?? live.sessions[key]` — карточка показывает
  выбранную сессию ещё до первого turn'а и после рестарта.
- `reset(ref)` обёртки не меняется: отсоединяет и очищает активную привязку,
  реестр не трогает.

### Чат — `packages/plugins/dsh-balbes-telegram/src/chat.ts`

- Новый снимок `SessionListSnapshot` (`kind: "sessionList"`): `chatId`,
  `mode: "active" | "archive"`, `rows: ChannelSessionRow[]`, `page`.
- `openSessions(chatId, messageId, mode, page)` читает `deps.sessions.list(ref)`,
  фильтрует по режиму, строит карточку и кладёт снимок; сбой чтения — безопасный
  текст + карточка меню (как у списка воркспейсов).
- `act:sessions` (кнопка меню) и команда `sessions` открывают активный список;
  `ses:arch` — архив; `ses:back` — назад к активному списку.
- Возврат `ses:<i>`: перечитывает строку из снимка, проверяет доступность и
  занятость; в режиме архива дополнительно возвращает сессию из архива
  (`unarchive`). При успехе зовёт `deps.sessions.select(ref, id)` и
  перерисовывает меню с подтверждением «Выбрана сессия: …»; при занятости — тост
  «Задача выполняется — дождитесь завершения или /stop»; недоступная —
  тост «Сессия недоступна».
- Архив `arc:<i>` / возврат `unarc:<i>`: зовёт `deps.sessions.archive` /
  `unarchive`, перерисовывает текущий снимок.
- `onMessage`: новая команда `sessions` → `openSessions(..., "active", 0)` как
  новое сообщение.

### Команды и карточки

- `commands.ts`: `CommandName` += `sessions`; в `TELEGRAM_COMMANDS` строка
  `{command: "sessions", description: "Сессии воркспейса: список, возврат, архив"}`.
  Таблица остаётся единственным источником и для `setMyCommands`, и для роутера.
- `cards.ts`:
  - `HELP_TEXT`: строка `/reset` переформулирована («начать новую сессию;
    прежние остаются в /sessions»), добавлена `/sessions`.
  - `menuCard`: строка состояния `Сессия: активна | не создана` сохраняется;
    в набор кнопок активного воркспейса добавляется **«🗂 Сессии»**
    (`act:sessions`). Раскладка (4 ряда):
    `[📄 Файлы][🧠 Модель]`, `[🗂 Сессии][📁 Воркспейс]`,
    `[🔄 Сбросить контекст][⏹ Стоп]`, `[🔄 Обновить]`.
  - `sessionsCard({workspaceLabel, rows, page, pages})` — заголовок
    `🗂 Сессии · <воркспейс>`, подсказка «Выберите сессию:», строки и футер.
  - `archiveCard({workspaceLabel, rows, page, pages})` — заголовок
    `🗄 Архив сессий · <воркспейс>`.
- `keyboards.ts`: `sessionsKeyboard` — строки
  `[{text: "• Title" | "Title", callback_data: "ses:<i>"}, {text: "🗄", callback_data: "arc:<i>"}]`,
  пагинация `ses:pg:<n>`, футер `[{«🗄 Архив», "ses:arch"}]` + `menuRow`.
  `archiveKeyboard` — строки
  `[{Title, "ses:<i>"}, {"↩", "unarc:<i>"}]`, пагинация, футер
  `[{«⬆ К сессиям», "ses:back"}]` + `menuRow`.

## Состояние (схема)

`$DSH_HOME/telegram-state.json`:

```json
{
  "version": 1,
  "activeWorkspace": "project:my-app",
  "sessions": { "project:my-app": "session-active" },
  "archived": { "project:my-app": ["session-old-1", "session-old-2"] },
  "offset": 123456789
}
```

- `sessions[воркспейс]` — активная сессия (единственная, как и раньше).
- `archived[воркспейс]` — скрытые из активного списка id; порядок не значим.
- Отсутствие ключа = пусто; пустые значения не пишутся.

## Telegram UX

### Команды

`/menu`, `/status`, `/ws`, `/model`, `/reset`, `/sessions`, `/stop`,
`/help` — регистрируются нативным `setMyCommands` с той же таблицы.

### Карточка-меню

Добавляет **«🗂 Сессии»**. Строка `Сессия:` в расширенном виде (`/status`)
по-прежнему показывает `активна` / `не создана` (по активной привязке, включая
выбранную до первого turn'а).

### Карточка «Сессии»

- Заголовок `🗂 Сессии · <воркспейс>`, подсказка «Выберите сессию:».
- Строка: `[• <заголовок>] [🗄]`; `•` — активная. Заголовок из движка; нет
  заголовка — «Без заголовка»; недоступная — с пометкой «(недоступна)».
- Футер: `[🗄 Архив]`, `[⬅ Меню]`; пагинация `◀ ▶` при нескольких страницах.
- Пусто: «Активных сессий нет» (если в архиве что-то есть) или
  «Сессий пока нет».
- Нажатие заголовка возвращает к сессии; `🗄` убирает в архив.

### Карточка «Архив»

- Заголовок `🗄 Архив сессий · <воркспейс>`.
- Строка: `[<заголовок>] [↩]`; нажатие заголовка возвращает к сессии и
  возвращает её из архива; `↩` только возвращает в активный список.
- Футер: `[⬆ К сессиям]`, `[⬅ Меню]`; пусто: «Архив пуст».

## Обработка ошибок и края

- Реестр недоступен или `list` бросил — карточка меню с безопасным текстом
  «Не удалось получить список сессий», без стека.
- `sessionQuery` не скомпонован — список строится по реестру: заголовок
  «Без заголовка», порядок — обратный порядок реестра, все сессии доступны.
- Снимок устарел (перезапуск, другой чат, чужой индекс) — «Список устарел» без
  действий, как у списка воркспейсов.
- `ses:<i>` при выполняющейся задаче или очереди — отказ-тост.
- Недоступная сессия — тост «Сессия недоступна», выбор не выполняется.
- Архив активной сессии отсоединяет хэндл; следующая задача создаёт новую.
- Возврат из архива активную привязку не трогает.
- Выбор сессии, пока задача выполняется, не меняет ни активную сессию, ни хэндл.
- Смена воркспейса делает открытый список сессий неактуальным: снимок привязан к
  воркспейсу, чужие индексы отсекаются проверкой снимка.
- Пустой `sessionId` не попадает ни в state (стор отвергнет), ни в активную
  привязку — та же защита, что сейчас.

## Открытые технические проверки до реализации

1. **Почему админка показывает одну сессию после `/reset` + продолжения.**
   По коду движка файлы сессий не удаляются, а реестр append-only, поэтому после
   `/reset` прежняя должна оставаться (и быть читаемой). Проверить на сервере:
   есть ли прежний id в `workspace-sessions.json` и читается ли он
   `sessionQuery`; вероятная причина — сессия создана до появления реестра.
   От этого зависит, увидят ли ранние сессии список `/sessions`.
2. **Resume после `reset`.** Подтвердить тестом, что сессия, отсоединённая
   `runner.reset`, снова резюмится по тому же id (основа неразрушающего
   `/reset`).
3. **`sessionQuery` без композиции.** Проверить, что канал работает и без него
   (деградация списка), и что необязательный `ctx.get` не делает сервис
   обязательным.
4. **Совместимость state.** Подтвердить, что старый `telegram-state.json`
   читается новым сторов без потери активной привязки и что невалидный
   `archived` не роняет загрузку молчаливым сбросом.

## Риски

- Реестр может содержать сессии старше самого реестра, которых в нём нет — их
  список не покажет; это ограничение данных, а не поведения.
- Без `sessionQuery` список теряет заголовки и сортировку по времени —
  приемлемая деградация, не ошибка.
- Очень большой архив: список и архив постраничны, поэтому размер не влияет на
  одну карточку.
- `/reset` по-прежнему прерывает выполняющуюся задачу (как сейчас); владелец
  может вернуться к прерванной сессии через `/sessions` — контекст сохранится.

## Отложено (не в этом шаге)

- Удаление и переименование сессий, очистка истории.
- Возврат к сессии другого воркспейса одним шагом.
- Управление сессиями из админки.
- Поиск, экспорт, ветвление, компактация контекста.
- Streaming ответа модели.
- Мультивладелец и несколько ботов (p6) — механика канала остаётся одним ботом.
