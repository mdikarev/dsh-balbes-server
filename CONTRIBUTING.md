# CONTRIBUTING — правила написания кода

Компактный свод того, как в этом репозитории пишется код (надстройка над dsh
на TypeScript, экосистема Cordis). Короткая версия для агентов — `AGENTS.md`.

## Рамки (не нарушать)

- **dsh — зависимость, не форк.** Установленные пакеты `@deepseek-ai/*` не
  редактируются. Ядро не модифицируется и не обходится: надстройка общается с ним
  только через штатные швы — сервисы и события Cordis, хранилища dsh, композиция
  Loader (профиль/патчи).
- **Своё реализуется механизмами dsh:** профиль (`dsh.profile.bundles`), патчи
  (`cordis.patch.yml`), собственные бандлы и плагины.
- **`docs/canon/**` вручную не редактируется** — только через `canon-write`;
  поведенческую работу закрывает `canon-audit`. При расхождении доков и кода не
  выбираем сторону молча.
- **Секреты не попадают в git:** ключи моделей, `.env`, локальное состояние dsh.
  CI работает без ключей.
- **Технологии:** TypeScript; без Python в надстройке.

## Шаблон структуры репозитория

Точный состав семей уточняется с первым кодом; правило одно — пакеты лежат по
своей роли, не вперемешку.

```
packages/
  bundles/     # бандлы: пакеты с "dsh": { "bundle": { "patch": ... } } —
               #   поставляют патч-слой композиции (готовые поверхности над ядром)
  plugins/     # обычные Cordis-плагины без dsh.bundle.patch: сервисы, api-роуты,
               #   тулы, ui-плагины; подключаются insert-записями в патч профиля
profiles/      # профили dsh, по одному на поверхность:
  <name>/      #   манифест dsh.profile + свой cordis.patch.yml + link: на packages/*
docs/          # canon (управляется doc-canon) и проектные документы
scripts/       # вспомогательные скрипты и гейты
```

- **Бандл** (композиция) кладётся в `packages/bundles/` и перечисляется в
  `dsh.profile.bundles` профиля.
- **Плагин** (одна возможность) кладётся в `packages/plugins/` и добавляется в
  профиль записью `insert: {id, name}`.
- **Профиль** — пакет без кода: манифест, свой `cordis.patch.yml`, ссылки на наши
  пакеты. Подключение своих пакетов — через `link:` (профиль держит собственный
  `pnpm-workspace.yaml` с `linkWorkspacePackages: true`).
- Бандл в списке `bundles` обязан иметь декларацию `dsh.bundle.patch`, иначе
  старт падает громко.

## Пакеты в экосистеме dsh

- Имя пакета: `dsh-balbes-<роль>` (kebab-case) — префикс `balbes` отделяет наши
  пакеты от пакетов движка. Неймспейс `@deepseek-ai` не занимаем.
- Манифест: `"type": "module"`, `main: "lib/index.js"`,
  `types: "lib/types/index.d.ts"`; `exports` минимум `"."` и `"./package.json"`;
  bundle дополнительно экспортирует `"./cordis.patch.yml"`. `files` — только
  собранное. Импорты из `@deepseek-ai/*` объявляются в зависимостях явно.
- **Функциональный плагин**: именованные экспорты `name` / `inject` / `Config` /
  `apply`, без default-экспорта. **Сервисный пакет**: default-экспорт класса —
  наследника `Service`. Смешивать нельзя: Loader теряет `name`/`inject`.
- Настройки — только валидируемые поля `Config` (схема на
  `@deepseek-ai/schemastery`); хардкод-тюнабелей в коде нет.
- Зависимости декларируются через `inject`; `ctx.<name>` — только для
  инжектированных сервисов; опциональный сервис — через строгий `ctx.get(name)`.
- Типизированные события — через declaration merging, с документированным
  режимом доставки (`@mode`); waterfall-listener обязан вызвать `next()`, иначе
  цепочка обрывается.
- **Регистрации — это эффекты**: вклад ставится через `ctx.effect()` /
  `ctx.on()` и откатывается при teardown/reload; `register()` возвращает disposer.
- Ключи `ctx`: единственное число — один сервис, множественное — реестр; имя
  называет роль (`Registry`, `Provider`, `Store`, `Controller`, `Resolver`, ...).
  Ключи и имена ядра dsh не переопределяются.
- Патчи: переопределение по `id` заменяет конфиг целиком (deep-merge нет);
  новые записи — `insert` под новыми `id` (уникальны в дереве). Пустой или
  только-комментарный `cordis.patch.yml` роняет старт — отключение слоя пишется
  как `[]`. `!!js` допустим в `config`/`disabled` записей (не `!js`).
  Композицию проверяем `dsh --dump-config`.

## TypeScript

- `strict` везде; каждый оставшийся `any` — с обоснованием. Закрытые union —
  `switch` с `assertNever`; расширяемые — документированный default.
- ESM; внутри пакета относительные импорты с расширением `.ts`, между пакетами —
  по имени пакета.
- Идентификаторы, пересекающие границы (session/run id и т.п.), — брендированные
  (`Branded<B>`), не голый `string`.
- Валидация на границах: конфиги, wire/JSON, файлы — валидируем; внутри
  типизированных границ одного процесса рантайм-проверки не дублируем.
- Модель-видимый текст (промпты, схемы тулов, сообщения) — только термины задачи;
  стабильные литералы выносятся и покрываются тестами.
- Пустой `catch` называет, что глотает и почему; комментарии локальные.
  Маркеры: `FIXME` (блокирует релиз), `TODO` (скоро), `XXX` (когда-нибудь).
- Именование: файлы kebab-case; функции/переменные camelCase; классы/типы
  PascalCase; константы UPPER_SNAKE; булевы — `is*/has*/should*`. Код и
  комментарии — на английском.
- Файлы: UTF-8, LF, ровно один перевод строки в конце, без висячих пробелов.

## Тесты

- vitest; тесты в `tests/` рядом с кодом (не `src/__tests__/`). Тест описывает
  поведение; меняется поведение — меняется тест в том же изменении.
- Product-visible требует REAL-композиции: поднимается тестовый `cordis.yml`
  через Loader/приложение; мокаются только внешние или недетерминированные
  границы (LLM-провайдер, сеть, часы).
- Тесты с внешними ключами самопропускаются без ключа — CI остаётся зелёным без
  секретов. Тест владеет своими ресурсами (порты, пути, процессы) и освобождает
  их в teardown. E2e-утверждения проверяют мир, а не самоотчёт агента.

## Перед «готово»

- Прогнать релевантные проверки по затронутой области: `pnpm typecheck`,
  `pnpm lint`, `pnpm test` (+ валидация композиции при правке бандлов/патчей).
- В отчёте — только фактически выполненные команды и их результат.
- README/JSDoc/канон обновляются в том же коммите, что и поведение.
- Один коммит = одно изменение; первая строка сообщения — глагол + суть до
  ~72 символов.
